# ลำดับที่คาดหวัง — คำนวณจากมาตรฐาน ก่อนเขียนโค้ด

⚠️ ไฟล์นี้เขียน **ก่อน** เขียน resolver และ **ก่อน** รันเทสต์ครั้งแรก
(บทเรียนโปรเจกต์: เทียบกับโมเดล ไม่ใช่สัญชาตญาณ · `pleng-compare-to-model-not-intuition`)
ห้ามแก้ตัวเลขในไฟล์นี้หลังเห็นผลรัน — ถ้าไม่ตรง ให้แก้ resolver

ทุกเคสใช้ห้อง (bar) ตั้งชื่อ A B C D E ตามลำดับที่เขียนบนกระดาษ

---

## (ก) เครื่องหมายซ้ำธรรมดา

กระดาษ:  `A  ‖: B  C :‖  D`

มาตรฐาน (Gould, *Behind Bars*, repeat signs · Wikipedia *Repeat sign*):
เล่นถึง `:‖` → ย้อนไปที่ `‖:` → เล่นซ้ำช่วงนั้นอีก 1 รอบ → เล่นต่อ

**คาดหวัง: `A B C B C D`**  (6 ห้อง)

## (ข) จบแบบ 1-2 (volta)

กระดาษ:  `A  ‖: B  C  [1. D :‖]  [2. E ]`

มาตรฐาน (Wikipedia *Repeat sign § Volta brackets*):
รอบ 1 = เล่น B C แล้วเข้ากล่อง 1 (D) เจอ `:‖` → ย้อน ·
รอบ 2 = เล่น B C แล้ว **ข้ามกล่อง 1** เข้ากล่อง 2 (E) → เล่นต่อจนจบ

**คาดหวัง: `A B C D B C E`**  (7 ห้อง)

## (ค) ย้อนต้นแล้วจบกลางเพลง (D.C. al Fine)

กระดาษ:  `A  B  C(Fine)  D  E(D.C. al Fine)`

มาตรฐาน (Wikipedia *Da capo* · *Dal segno*):
เล่นตั้งแต่ต้นจนจบบรรทัด (ผ่าน Fine ครั้งแรก **ไม่หยุด**) → ถึง D.C. → กลับไปห้องแรก →
เล่นใหม่จนถึง Fine → **หยุดที่ Fine**

**คาดหวัง: `A B C D E A B C`**  (8 ห้อง)

### หมายเหตุมาตรฐานที่ต้องเคารพในเคส (ค)
- Fine **ไม่มีผลในรอบแรก** — มีผลเฉพาะหลังกระโดดแล้ว (นี่คือจุดที่ resolver พลาดง่ายสุด)
- ธรรมเนียมสากล: รอบ D.C. **ไม่เล่นเครื่องหมายซ้ำซ้ำอีก** เว้นแต่เขียน *con repetizione*
  → เคส (ค) จึงจงใจไม่มี `‖: :‖` เพื่อไม่ผสมความกำกวมเข้ามาในเทสต์ที่ควรฟันธง
