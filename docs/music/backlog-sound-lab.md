# Backlog — "Sound Lab" (โหมดทดสอบเสียงในแอป สำหรับคนทำดนตรี)

**สถานะ:** backlog (P'Aim สั่งเก็บ 18 ก.ค. · ยังไม่ทำ) · **เจ้าของไอเดีย:** P'Aim · **สาย:** music → ต้องผ่าน PM/UX/dev เพื่อเข้าแอปจริง

## ไอเดีย (P'Aim)
> "อยากมีโหมดทดสอบ/หน้าทดสอบ สำหรับคนทำเสียงดนตรีในแอป จะได้ลองเล่นเทคนิคต่างๆ ในเพลงต่างๆ ได้ — อย่างตัวปรับจูนที่เราคุยกัน ผมจะได้ลองเล่นได้"

## ทำไมคุ้ม
- ตอนนี้การจูนเสียง (เชลโล/เปียโน) ทำใน **spike แยก** (`docs/spikes/cello-listen.html`) ที่รันจาก dev server เท่านั้น — พี่เอม/คนทำเสียงต้องพึ่ง session ของ Claude เปิดให้
- ถ้ามี **"Sound Lab" ในแอปจริง** → คนทำเสียงเปิดเองได้ทุกเมื่อ · ลองเทคนิค (สูตรกลาง) กับเพลงไหนก็ได้ · หาค่าที่เพราะด้วยหูเอง แล้วบันทึกเป็น preset — โดยไม่ต้องแตะโค้ด
- เป็น "โต๊ะทำงาน" ของสาย music ถาวร (เหมือนที่ golden piano / เชลโล ถูกจูนมา)

## ต้นแบบที่มีอยู่แล้ว (reuse ได้เกือบทั้งหมด)
**`docs/spikes/cello-listen.html` + `src/spikes/celloListenPage.js` + `renderClip()` ใน `celloBakeoff.js`** — มีครบ:
- เลือกเพลง (dropdown ทั้งคลัง) + ท่อนสั้น/ทั้งเพลง
- นาฬิกา + ชื่อโน้ตที่กำลังเล่น (ชี้ artifact ได้)
- player เล่นทีละอัน + ปุ่มหยุด
- ปุ่มจูนครบ (สูตรกลางทุกตัว): ความสม่ำเสมอเนื้อเสียง (treble shift-based) · ความสม่ำเสมอความดัง (compressor) · สั่นนิ้ว · หัวโน้ต · เลื่อนเวลา · เส้นดัง-ค่อย · ระยะห่าง/ห้อง (chamber) · ฯลฯ

## สิ่งที่ต้องเพิ่ม/ปรับ ถ้าจะเข้าแอปจริง (งาน integration — คนละเรื่องกับการทำเสียง)
1. **เป็นหน้าในแอป** (route เช่น `/studio/sound-lab` หรือใน Studio) แทน spike แยก
2. **จำกัดสิทธิ์ = ทีม/คนทำเสียงเท่านั้น** (ไม่ใช่ผู้ใช้ทั่วไป/พี่น้องคริสเตียน) — เหมือน gate อื่นในแอป
3. **แยก engine spike → engine จริง:** ตอนนี้ `celloBakeoff.js` เป็น spike · ต้องตัดสินใจว่าจะ (ก) ยกเทคนิคเข้า `src/lib/arranger/` + `midi.js` แบบ preset "เชลโล" หรือ (ข) คงเป็น lab แยก
4. **บันทึก/ตั้งชื่อ preset ต่อเครื่องดนตรี** — หาค่าเพราะแล้ว save เป็น "เชลโลบรรเลง v1" ใช้ได้ทั้งคลัง (default ปัจจุบันของเชลโลเป็นจุดตั้งต้น)
5. **sample เชลโล = ต้อง ship จริง** (ตอนนี้ gitignored · build จาก Karoryfer) + PWA size (`p`-layer ~0.9MB · lazy-load) — memory `pleng-pwa-self-host-samples`
6. **เอาเชลโลเข้า SongView จริง** (`soundOptions.js` เชลโล `disabled:true`) = ตัดสินใจแยก (ผู้ใช้เลือกเสียงเชลโลได้ไหม)

## ข้อควรระวัง
- Lab นี้ = เครื่องมือ **ภายใน** · ปุ่มทดลอง (arc/round-robin/resonance) อาจให้ผลแปลกๆ — ต้องมี "รีเซ็ตกลับ default ที่เคาะแล้ว" เสมอ
- ทุกปุ่ม = สูตรกลาง (key ต่อโน้ต) ทำงานทุกเพลง — ห้ามกลายเป็นจูนรายเพลง (หลัก P'Aim · memory `pleng-cello-shift-artifact`)
- ต้องมี tester + PM gate เหมือน feature อื่น (นี่คือ scope PM ไม่ใช่ music seat ทำเดี่ยว)
