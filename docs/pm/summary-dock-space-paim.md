# คืนพื้นที่หน้าจอ — ให้แถบเครื่องมือ “หลบเอง” (สรุป 1 หน้า)

## รากของปัญหา (ที่พี่เอมชี้)

แถบเครื่องมือถาวรกินพื้นที่จอ **แย่งที่กับเนื้อเพลง**ที่พี่เปากำลังแก้ → ใช้งานยาก

**การให้ผู้ใช้ “ลากย่อแถบเอง” = แก้ปลายเหตุ** — พี่เปาต้องมานั่งย่อ และย่อแล้วแถบก็ยังกินที่อยู่ดีตลอดเวลา

## ทางแก้ระดับโลก (ฟันธง) — แถบ “มีเงื่อนไข” ไม่ใช่ “เล็กลง”

ผมเปิดดูวิธีของแอประดับโลกจริง (Safari, Google Docs, Material) — **ทุกเจ้าไม่ได้ทำแถบให้เล็กลง แต่ทำให้มัน “โผล่เฉพาะตอนต้องใช้”** แล้วหลบให้เนื้อหาเวลาไม่ใช้ → เอาหลักนี้มา 3 จังหวะ:

1. **เลื่อนอ่าน → แถบหลบเอง** (เหมือนแถบที่อยู่เว็บบนมือถือที่หายตอนเลื่อน) · เลื่อนกลับ/แตะ → แถบกลับมา
2. **แตะโน้ต/บรรทัด → เครื่องมือมาหาตรงนั้น** (ไม่ต้องมีแถบใหญ่ถาวร — นี่คือ “toolbox ติด element” ที่ผมออกแบบไว้ก่อนหน้า เอากลับมาใช้พอดี)
3. **พิมพ์อยู่ → แถบซ่อน เครื่องมือเกาะเหนือแป้นพิมพ์** (เหมือน iPhone/Google Docs) เพราะแป้นบังแถบล่างอยู่แล้ว

+ แถบเริ่มต้น = **เฉพาะปุ่มที่ใช้บ่อยจริง** ที่เหลือเก็บใน ⚙ · (ลากย่อ/โปร่งใส = ของเสริม ไม่ใช่คำตอบหลัก)

## ทำไมดีกว่าให้ลากย่อ

ลากย่อ = พี่เปาต้องจัดการเอง + แถบยังอยู่กินที่ · **หลบเอง = พื้นที่คืนอัตโนมัติเมื่อไม่ได้ใช้ + เครื่องมือมาหาที่ทำงาน** → ได้จอเต็มไว้อ่าน/แก้เพลง

## ไม่ทิ้งใคร (คนพิการ)

โหมด screen reader → แถบ **ไม่หลบอัตโนมัติ** (ไม่งั้นคนใช้เสียงจะหาแถบไม่เจอ) — เป็นข้อบังคับตามมาตรฐาน (Material เตือนไว้)

## ทำเป็นกี่เฟส

- **เฟส A (แก้ root ตรงสุด):** แถบหลบตอนเลื่อน + แถบบางเฉพาะปุ่มสำคัญ + โหมดคนพิการ
- **เฟส B:** เครื่องมือมาหา element ที่แตะ (โน้ต/ห้องก่อน)
- **เฟส C:** พิมพ์ → แถบซ่อน เครื่องมือเหนือแป้น + ครบทุกระดับ
- **เฟส D:** ลากย่อ/โปร่งใส เป็นของเสริม (ถ้ายังอยากได้)

**งานนี้ใหญ่กว่าเดิม** (แตะแนวคิดพื้นที่ของหน้าแก้ไขทั้งหมด) — SA ตรวจว่าทำได้ · แตะไฟล์หลัก 2 ตัว build ต้องเข้าคิว
