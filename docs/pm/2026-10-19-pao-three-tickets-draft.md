# ร่างใบงานย้อนหลัง 3 ใบ — เรื่องที่พี่เปาแจ้ง 19 ต.ค. 2569

สถานะ: **ร่าง รอพี่เอมเคาะ** — ยังไม่ได้เปิดบนอัมกิต

1. กติกา `aimagin-assign` ข้อ "ก่อนเปิดใบ" ห้าม AI เปิดใบก่อนเจ้าของงานอนุมัติ ให้ร่างเป็นไฟล์ `.md` ให้ดูก่อน ไฟล์นี้คือร่างนั้น
2. เซสชันนี้เป็น Claude Code บนคลาวด์ ต่อ https://git.aimagin.com ไม่ได้ (proxy ตอบ 403) และไม่มี `GITLAB_TOKEN_AI_COMPANY` จึงยิง API เปิดใบเองไม่ได้ ต่อให้เคาะแล้ว
3. เคาะแล้วทำได้ 2 ทาง
- 3.1 พี่เอมก๊อปเนื้อแต่ละใบไปเปิดเอง
- 3.2 หรือสั่งผมในเซสชันที่ต่ออัมกิตได้ ผมเปิดให้ตามร่างนี้
4. เปิดใบครบแล้ว **ให้ลบไฟล์ร่างนี้ทิ้ง** ตามกติกา `aimagin-assign`
5. ของที่ผมยังไม่รู้ และต้องให้พี่เอมเติมก่อนเปิดใบ
- 5.1 ชื่อบัญชีผู้รับผิดชอบและ cc ต้องเป็น `@username` คนจริง ผมไม่รู้ชื่อบัญชีของใครในอัมกิต จึงเว้นไว้
- 5.2 ที่เก็บใบ ควรเป็น `follow-up/customer` หรือ `follow-up/internal` — พี่เปาเป็นคนในทีมที่ใช้งานจริง ผมเดาว่า `internal` แต่ไม่ยืนยัน
- 5.3 มีใบรับเรื่องแม่ของรอบนี้อยู่แล้วหรือยัง ถ้ามี ทั้ง 3 ใบต้องเปิดเป็นงานย่อยใต้ใบแม่ ไม่ใช่เปิดใบใหม่คู่ขนาน
- 5.4 แม่แบบ WPA ทางการอยู่ที่ https://git.aimagin.com/aimagin/sop/-/tree/main/iso-29110-5-4/templates ผมเปิดไม่ได้ จึงเขียนตามชื่อหัวข้อที่สกิลระบุไว้ ขอให้ทาบกับแม่แบบจริงอีกรอบก่อนเปิด
6. หมุดหมายของทั้ง 3 ใบ: `2026-10 ครึ่งหลัง`
7. ทั้ง 3 ใบลงมือและส่งของแล้ว อยู่ในคำขอรวมเดียวกัน จึงเปิดใบในสถานะที่รอตรวจรับได้เลย

# ใบที่ 1 — WPA.04 Defects of software components

**ชนิด** ของเดิมไม่ผ่านที่สัญญาไว้ เป็นบั๊ก จึงใช้ WPA.04 ไม่ใช่ฟอร์ม 5 หัวข้อ

**ชื่อใบ** แก้เนื้อเพลงแล้วบางคำหายไปเอง ในกล่องแก้เนื้อแบบย่อหน้า

## Initial problem

1. พี่เปาแจ้ง 19 ต.ค. 2569 ว่า "การแก้ไขในเนื้อเพลงบางทีเนื้อหาย ไม่รู้ทำไม"
2. ที่มา: ภาพหน้าจอกล่อง "แก้เนื้อแบบย่อหน้า" ของเพลง 129 ใจกล้ามายังที่นั่งกรุณา ท่อนนั้นขึ้นว่า 66/68 คือมีโน้ตที่ต้องมีคำ 68 ตัว แต่มีคำอยู่ 66 ตัว
3. ความรุนแรง: **สูง** เพราะเป็นการสูญหายของงานที่พิมพ์ไปแล้ว ไม่ใช่แค่แสดงผลเพี้ยน และเกิดเงียบ ไม่มีข้อความเตือน
4. ต้นเหตุที่ตรวจพบ
- 4.1 กล่องแก้เนื้อแบบย่อหน้าอ่านกลับมาเฉพาะคำที่อยู่บนโน้ตที่ขึ้นเสียงใหม่ และเขียนกลับลงเฉพาะช่องนั้นเหมือนกัน
- 4.2 คำที่ไปอยู่บนช่องโน้ตลากเสียงหรือตัวหยุด จึงไม่ปรากฏในกล่อง นี่คืออาการ "เนื้อหาย" ที่เห็นบนจอ
- 4.3 พอพิมพ์ต่ออีกตัวเดียว กล่องจะเขียนทั้งข้อใหม่จากสิ่งที่กล่องแสดงอยู่ คำที่ไม่ปรากฏจึงถูกลบจริง
- 4.4 ปุ่ม แยกพยางค์อัตโนมัติ วิ่งผ่านทางเดียวกัน กดครั้งเดียวก็ลบคำพวกนั้นเช่นกัน
5. คำไปอยู่บนช่องลากเสียงได้ด้วยวิธีใช้งานปกติ ไม่ใช่การใช้ผิด
- 5.1 ปุ่มเลื่อนพยางค์ซ้ายขวา วิ่งผ่านทุกช่อง ไม่ได้ข้ามช่องลากเสียง
- 5.2 แก้ทำนองให้โน้ตกลายเป็นลากเสียง ทั้งไท ตัวหยุด และการครอบวงเล็บสเลอร์สำหรับเอื้อน จำนวนช่องเท่าเดิม ตัวย้ายคำจึงไม่ขยับอะไร คำอยู่ที่เดิมแต่ช่องเปลี่ยนชนิดไปแล้ว
6. ส่วนที่เสีย: `src/components/EditorMode.vue` ฟังก์ชัน `syllablesToWords` และ `wordsToSyllables`

## วิธีทำซ้ำให้เห็นอาการ

1. เปิดหน้าแก้ไข เลือกเพลงที่มีเอื้อนหรือโน้ตลากเสียง
2. พิมพ์คำลงช่องใต้โน้ตลากเสียง หรือกดปุ่มเลื่อนพยางค์จนมีคำไปอยู่บนช่องลากเสียง
3. กางกล่อง แก้เนื้อแบบย่อหน้า จะเห็นว่าคำนั้นหายไปจากกล่องแล้ว
4. พิมพ์อะไรก็ได้ในกล่องอีก 1 ตัว คำนั้นหายจากเพลงจริง

## Solution defined

1. กล่องแก้เนื้อแบบย่อหน้าต้องอ่านทุกคำที่มีอยู่ ไม่ว่าคำนั้นอยู่บนช่องชนิดไหน
2. กล่องแก้เนื้อแบบย่อหน้าต้องเขียนทุกคำกลับคืน ไม่มีคำไหนหายระหว่างทาง
3. คำที่ผู้แก้ไม่ได้แตะ ต้องอยู่ช่องเดิม แก้คำผิดคำเดียวหรือเติมคำท้ายข้อ ต้องไม่ดันทั้งข้อ
4. ปุ่มแยกพยางค์อัตโนมัติ ต้องไม่ลดจำนวนคำที่มีอยู่
5. การวางเนื้อทั้งข้อลงเพลงเปล่า ต้องยังลง 1 คำต่อ 1 โน้ตขึ้นเสียงเหมือนเดิม ไม่ใช่ถือโอกาสเปลี่ยนพฤติกรรมนี้
6. **ไม่อยู่ในงานนี้** คือการกู้คำที่หายไปแล้วในเพลงที่โดนก่อนหน้านี้ ของพวกนั้นต้องไปไล่จากประวัติการแก้ไขของแต่ละเพลงเอง

## Verification

1. เทสต์อัตโนมัติ `src/components/EditorMode.lyriclost.test.js` ต้องผ่านครบ 9 ข้อ
2. เทสต์ชุดนี้ต้องตกอย่างน้อย 7 ข้อเมื่อเอาโค้ดเดิมกลับมา ถึงจะพิสูจน์ว่าทดสอบตรงบั๊กจริง
3. เทสต์ทั้งคลังต้องผ่านครบ และ `npm run build` ต้องผ่าน
4. พี่เปาเปิดเพลงที่เคยเจออาการ แล้วยืนยันว่าแก้เนื้อแล้วคำไม่หาย

## หมายเหตุ

1. คนทำไม่ใช่คนตรวจรับงานตัวเอง ใบนี้ต้องให้คนอื่นตรวจรับ
2. รายงานสถานะใช้สกิล `aimagin-status` ขออนุมัติใช้สกิล `aimagin-request`

# ใบที่ 2 — WPA.03 Change request

**ชนิด** ผู้ใช้ขอของใหม่ จึงใช้ WPA.03 ไม่ใช่ WPA.04

**ชื่อใบ** เพิ่มช่องอ้างอิงเล่มอื่นในหน้าแก้ไข พิมพ์เองได้ และใส่ได้หลายเล่ม

## เรื่องที่ขอ

1. พี่เปาแจ้ง 19 ต.ค. 2569 ว่า "อยากให้เพิ่มช่องอ้างอิงเพลงเข้าไปด้วยค่ะ เช่น (ล.305) ประมาณนี้ แต่ต้องให้เขียนได้เองเลยเพราะจะมีตัวย่อหลายตัว บางเพลงอ้างอิงหลายอันค่ะ"
2. ของเดิมมีอยู่แล้วครึ่งทาง คือคอลัมน์ `songs.book_refs` ที่นำเข้ามาจาก DA และแสดงอยู่ที่หน้าแรกกับหน้าฝึกร้องแล้ว แต่ **หน้าแก้ไขไม่มีช่องให้พิมพ์** ของจึงเพิ่มเองไม่ได้เลย
3. ชื่อเล่มย่อที่ระบบรู้จักมี 9 ตัวใน `src/lib/bookCodes.js` แต่พี่เปาบอกเองว่ามีตัวย่อมากกว่านั้น ช่องจึงต้องเป็นข้อความอิสระ ไม่ใช่ดรอปดาวน์

## เสร็จเมื่อ

1. หน้าแก้ไขมีช่องอ้างอิงในการ์ดตั้งค่าเพลง พิมพ์ข้อความอิสระได้
2. ใส่หลายเล่มในช่องเดียวได้ คั่นด้วยเว้นวรรค จุลภาค อัฒภาค หรือจุดกลาง
3. ก๊อปข้อความที่มีวงเล็บ เช่น (ล.305) มาวางได้เลย ระบบตัดวงเล็บให้เอง
4. ตัวย่อที่ระบบยังไม่รู้จักก็พิมพ์ได้ และยังแสดงผลกับค้นหาเจอ
5. พิมพ์ชื่อเล่มเต็ม เช่น เล่มเล็ก 305 ต้องเก็บเป็นรหัสเล่มเดียวกับของที่นำเข้ามา จะได้ไม่กลายเป็นคนละเล่ม
6. ใต้ช่องบอกคำอ่านสดว่าที่พิมพ์ไปถูกไหม
7. เปิดเพลงที่มีอ้างอิงอยู่แล้ว เห็นของเดิมในช่อง และลบทิ้งได้จริง
8. อ้างอิงที่พิมพ์ขึ้นครบทั้งหน้าแรก หน้าฝึกร้อง และค้นหาด้วยเลขเล่มเจอ เหมือนของที่นำเข้ามา
9. เพลงที่ไม่เคยมีอ้างอิง ข้อมูลเพลงต้องไม่มีคีย์เพิ่มขึ้นมาเปล่า ๆ
10. **ไม่อยู่ในงานนี้** คือการแก้หน้าแผ่นเพลงให้พิมพ์อ้างอิงลงกระดาษ พี่เปาไม่ได้ขอ

## Suggestion

1. ทางเลือกที่ตรงไปตรงมาคือเพิ่มคอลัมน์ `book_refs` ให้ตาราง `song_drafts` แล้วแก้ฟังก์ชัน `approve_and_publish` ด้วย แต่ท่านั้นต้องรัน SQL ก่อนโค้ดขึ้น ถ้าลำดับสลับ การบันทึกจะพังทั้งระบบ
2. เลี่ยงได้โดยเก็บใน `content.bookRefs` เพราะ `content` เดินทางครบวงจรอยู่แล้วตั้งแต่ร่างจนเผยแพร่ ไม่ต้องย้ายฐานข้อมูลและไม่ต้องแก้ฟังก์ชัน
3. ถ้าเลือกท่าที่ 2 ต้องมีจุดอ่านที่เดียว ไม่งั้นจะมีแหล่งความจริงสองที่ แล้วหน้าจอแต่ละหน้าจะไม่ตรงกัน

# ใบที่ 3 — WPA.03 Change request

**ชนิด** ผู้ใช้ขอของใหม่ จึงใช้ WPA.03

**ชื่อใบ** ช่องธีมในหน้าแก้ไข ต้องพิมพ์ธีมใหม่เองได้

## เรื่องที่ขอ

1. พี่เปาแจ้ง 19 ต.ค. 2569 ว่า "และธีมให้เพิ่มได้เองด้วย ตอนนี้มันเพิ่มไม่ได้มีแค่ให้เลือกเท่าที่มีอยู่"
2. ของเดิมช่องธีมเป็นดรอปดาวน์ที่ล็อกไว้ 8 ธีม เพลงที่ไม่เข้าพวกจึงต้องปล่อยว่าง
3. ธีมไม่ใช่สิ่งที่ฐานข้อมูลบังคับรายการไว้ ต่างจากช่องหมวดซึ่งเป็นเล่ม และตั้งใจล็อกไว้ 3 เล่มจริง ๆ

## เสร็จเมื่อ

1. ช่องธีมรับข้อความอิสระ พิมพ์แล้วกด Enter หรือคลิกออกก็ติด
2. ธีมที่มีเพลงในคลังใช้อยู่แล้ว ต้องขึ้นในรายการให้เพลงถัดไปเลือก คือพิมพ์ครั้งเดียว ไม่ต้องพิมพ์ซ้ำทุกเพลง
3. เว้นวรรคล้วนต้องไม่นับเป็นธีม
4. พิมพ์ยาวเกินกำหนดต้องบอกเหตุผลใต้ช่อง ไม่ใช่เด้งกลับเงียบ ๆ
5. ธีมที่พิมพ์เองต้องนับเป็นค่าจริงตามกติกา B108 คือเผยแพร่ทับของเดิมได้อย่างปลอดภัย
6. **ช่องหมวดต้องยังล็อก 3 เล่มเหมือนเดิม** และต้องมีเทสต์กันไว้ว่าการปลดล็อกธีมไม่ไปปลดล็อกหมวด
7. **ไม่อยู่ในงานนี้** คือหน้าจัดการธีมสำหรับแอดมิน เช่น เปลี่ยนชื่อธีมทั้งคลังหรือลบธีมที่ไม่ใช้ อันนั้นเป็นงานคนละใบ

## Suggestion

1. เรื่องปลดล็อกช่องหมวดเคยถูกเคาะไว้แล้วว่า **ห้าม** เมื่อ 12 ก.ค. 2569 ใบนั้นคือ B095 งานนี้ต้องไม่ไปแตะ
2. การเพิ่มหน้าแอดมินจัดการธีมเคยถูกตั้งเป็น B096 และพักไว้ ถ้าธีมเริ่มมั่วเพราะพิมพ์ผิด ค่อยยกใบนั้นขึ้นมาทำ
