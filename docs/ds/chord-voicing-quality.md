# DS — คุณภาพ/ความไพเราะของเสียงคอร์ดคลอ (B106)

**Task:** B106 (SA · R&D) · **base:** `studio-shell-redesign` · **branch:** `b106-sa-chord-quality`
**ต่อยอดจาก:** B104 (คอร์ดคลอ 3 โหมด · deploy แล้ว `b7341ee`) · สเปกเดิม `docs/ds/midi-chord-accompaniment.md`
**ที่มา (P'Aim ฟัง live):** "เสียงดีขึ้นเยอะกว่าทำนองล้วน **แต่คอร์ดอาจดังไป** · มี combination ที่ไพเราะกว่านี้ไหม ทั้งเชิงโปรแกรมและทฤษฎีดนตรี?"

---

## สรุปสั้น (F60+)

**2 เรื่องแยกกัน แก้ได้ทั้งคู่ · ไม่ต้องเพิ่ม library · เป็นงานเล็ก-กลาง.**

1. **"คอร์ดดังไป" = จริง และวัดได้.** ตอนนี้คอร์ดตี 4-5 เสียงพร้อมกัน เสียงละ 0.12 (ทำนอง 0.35) — ฟังเผิน ๆ เหมือนเบากว่า แต่ (ก) 4-5 เสียงซ้อนกันดัง**รวม**เท่า ๆ ทำนอง (แค่ **−2 ถึง −3 dB**) และ (ข) คอร์ด**ค้างยาวตลอด** ส่วนทำนองเป็นโน้ตสั้น ๆ มีช่องว่าง → หูได้ยินคอร์ดเป็น "กำแพงเสียง" กลบทำนอง. แก้ด้วยการลด gain ต่อเสียง + จัดบัสเสียงคอร์ด (low-pass + compressor) ให้คอร์ดรวมอยู่ **~−9 dB ใต้ทำนอง**.
2. **"ไพเราะกว่านี้ได้" = ได้ และตัวที่คุ้มสุดคือ voice-leading.** ปัญหาความไพเราะไม่ได้อยู่ที่ "โน้ตคอร์ดผิด" แต่อยู่ที่ **การเรียงเสียง (voicing)**: ตอนนี้เป็น block ราก-position ทุกคอร์ด → เสียงกระโดดเป็นก้อน และคอร์ดรากสูง (A/B/G7) เสียงบนไต่ขึ้นไป**ทับย่านทำนอง** (พิสูจน์แล้ว: Am ปัจจุบัน = A2 A3 C4 **E4** — E4 ชนทำนอง). ทำ **voice-leading** (เลือกพลิกคอร์ดให้เสียงบนขยับจากคอร์ดก่อนหน้าน้อยที่สุด) → คอร์ดคลอลื่นเหมือนออร์แกน/สตริง ไม่กระโดด ไม่ทับทำนอง. **ไม่ต้องรู้จังหวะ · เสี่ยงต่ำ · โค้ดเพิ่ม ~30 บรรทัด.**

**เดโมฟังด้วยหูพร้อมแล้ว** (§6) — P'Aim กดเทียบได้เลยก่อนเคาะ.

## 0. อัปเดตรอบ 2 — หลัง P'Aim ฟังจริง (ทิศทางใหม่: palette เลือกได้)

P'Aim ฟังเดโมรอบแรกแล้วให้ feedback (สำคัญ · เปลี่ยนทิศทาง deliverable):
- **"คลอค้าง voice-led" (ข้อ 2/3) เพราะแล้ว** ✅ — แต่ voice-led ค้าง vs polished ค้าง **แทบไม่ต่าง** (ถูก — ทั้งคู่เป็น block ค้าง ต่างแค่ความลื่นของเสียงบน ซึ่ง subtle).
- **"arpeggio ไล่เสียง" แปลกดี** — ต่างชัด.
- **อยากได้ตัวเลือกให้ผู้ใช้เลือกเอง** ว่าจะเอาสไตล์ไหน + **ขอสไตล์ที่เพราะ/ต่างมากกว่านี้อีก**.

**บทเรียน:** ความ "ต่างที่หูจับได้" มาจาก **จังหวะการตี (rhythm) + เสียง (timbre)** มากกว่าการเรียงโน้ต. voice-leading ยัง**สำคัญ** (ทำให้ทุกสไตล์ลื่น ไม่ทับทำนอง) แต่ทำงาน "เบื้องหลัง" — มันคือ**ชั้นเลือกโน้ต** ใต้ทุกสไตล์ ไม่ใช่ตัวสร้างความต่าง.

### 🎯 deliverable ปรับเป็น: "ชั้นความเพราะ 3 ระดับ" + palette เลือกได้
```
ชั้นที่ 1 — โน้ต    : voice-leading  (ใต้ทุกสไตล์ · แก้ทับทำนอง+ลื่น)         ← ทำเสมอ
ชั้นที่ 2 — จังหวะ  : ค้าง / ไล่ / รูด / ย่ำ  (rhythm pattern)               ← ตัวเลือกหลัก
ชั้นที่ 3 — เสียง   : triangle เดี่ยว / chorus 2-osc / swell (timbre+env)   ← ทำให้ "ต่าง+เพราะ"
+ ชั้น mix (§1)     : gain balance + low-pass + compressor                  ← ทำเสมอ
```

**palette ที่เสนอ (เดโมรอบ 2 มีให้ฟังครบ · §6):** ผู้ใช้เลือก 1 สไตล์ (เหมือนเลือกโหมดเสียง 3 แบบ) —

| สไตล์ | จังหวะ | timbre/env | คาแรกเตอร์ | เหมาะกับ |
|---|---|---|---|---|
| **คลอค้าง** (sustain) | 1 ก้อน/คอร์ด ค้าง | triangle + lowpass | นุ่ม เรียบ (พี่ว่าเพราะแล้ว) | ทั่วไป · default |
| **ไล่เสียง** (arpeggio) | ไล่ทีละตัวตามบีต | triangle สั้น | โปร่ง มีจังหวะ | เพลงช้า-กลาง |
| **★ รูดคอร์ด** (harp roll) | ตีพร้อมแต่เหลื่อม ~30ms | triangle decay | หวาน เหมือนดีดพิณ/กีตาร์รูด | เพลงช้า อ่อนหวาน |
| **★ สตริงคลอ** (string pad) | ค้าง | **2-osc chorus + swell ช้า** | ฟุ้ง อบอุ่น เหมือนสตริง/ออร์แกน | นมัสการช้า สงบ |
| **จังหวะย่ำ** (waltz/oom-pah) | เบสบีต1 + คอร์ดย่ำ 2-3-4 | triangle สั้น | คึกคัก มีชีพจร | เพลงเร็ว/สนุก |

**คำแนะนำใหม่ (แทน §3 เดิม):** ทำ **voicing-style selector** (ตัวเลือกสไตล์) เป็นฟีเจอร์ = "voicing v2 ที่ P'Aim เอ่ยไว้ตั้งแต่ B104" — ผู้ใช้เลือกได้ · จำค่า (localStorage). เริ่ม curate **3-5 สไตล์** จากตารางบน. ทุกสไตล์ใช้ voice-leading (ชั้น 1) + mix (§1) ร่วมกัน. **สไตล์ที่คาดว่า "เพราะสุด/ต่างสุด" = รูดคอร์ด + สตริงคลอ** (ให้ P'Aim เคาะจากหูในเดโม).

### "มีเทคนิคดนตรีอะไรอีกไหม" (P'Aim ถาม) — คลังเทคนิคเพิ่มความเพราะ
เรียงตามชั้น · ที่ทำในเดโมแล้วมี ✅ · ที่เหลือคือ future ต่อยอดได้:
- **โน้ต/ฮาร์โมนี:** voice-leading ✅ · inversions ✅ · **drop-2 voicing** (ดึงเสียงที่ 2 จากบนลงอ็อกเทฟ = คอร์ดกว้าง โปร่ง อิ่มแบบแจ๊ส) · **open voicing** (กระจายเสียงห่าง = โอ่อ่า) · **pedal/drone bass** (เบสรากค้างยาวใต้เสียงบนที่ขยับ = ฟีลออร์แกนโบสถ์) · **added tension** (maj7/add9/6 = สีสันหวานแบบ contemporary — แต่ต้องเป็น flag opt-in เพราะเสี่ยงชนทำนอง §5).
- **จังหวะ/แพตเทิร์น:** sustain ✅ · arpeggio ✅ · harp-roll ✅ · waltz/oom-pah ✅ · **Alberti bass** (ต่ำ-สูง-กลาง-สูง) · **ballad fingerpick** (เบส + รูดเบา ๆ ต่อบีต) · **walking bass** (เบสเดินเชื่อมคอร์ด — ต้องรู้คอร์ดถัดไป).
- **เสียง (timbre) — คันโยกความเพราะที่แรงสุดและยังไม่ได้ใช้ใน B104:** **chorus (2 osc เพี้ยนกันนิด)** ✅ (ข้อ 5) · **swell env ช้า** ✅ · **waveform ที่นุ่มกว่า** (sine = อุ่นเรียบ) · **low-pass ให้อุ่น** ✅ · **reverb/echo เบา ๆ** (ConvolverNode/feedback delay = มีมิติ ฟุ้ง เหมือนอยู่ในโบสถ์ — future, คุ้มมากกับเสียงนมัสการ) · **stereo spread** (แผ่เสียงซ้าย-ขวา = กว้าง).
> เทคนิคที่ให้ "เพราะขึ้นแบบรู้สึกได้ทันที" ต่อแรงลงน้อยสุด = **chorus + swell (timbre)** และ **reverb เบา ๆ** (future). เพราะหูคนจับ "เนื้อเสียง" ก่อน "การเรียงโน้ต".

### 🎹 อัปเดตรอบ 3 — เสียงเครื่องดนตรีจริง (sampled instruments) = คันโยกความเพราะที่ใหญ่ที่สุด
P'Aim ฟังแล้วบอก "เสียงยังทื่อ อยากได้เปียโน/สตริงเพราะ ๆ เหมือนที่เขาทำเพลงด้วยคอมกัน (MIDI + VSTi)". **คำตอบ: ทำได้ · และทำในเบราว์เซอร์เราได้ (ไม่ต้องมี DAW/ไฟล์ MP3 ต่อเพลง).**

**หลักการ:** เรามี "โน้ต" อยู่แล้ว (= MIDI ของเรา — `songToNotes`). สิ่งที่ทำให้เสียงทื่อคือ **เครื่องดนตรี** (ตอนนี้ = oscillator สังเคราะห์สด). แค่สลับเครื่องดนตรีจาก oscillator → **ไฟล์เสียงเครื่องจริงที่อัดไว้ (sample)** ก็ได้เสียงเปียโน Steinway จริง/สตริงจริง — **เล่นสดในเว็บ ยังทรานสโพส/เปลี่ยนคีย์/ความเร็วได้เหมือนเดิม** เพราะเรายังขับด้วยโน้ตเหมือนเดิม.

- **ทำได้จริง — พิสูจน์แล้วในเดโมรอบ 3:** ใช้ไลบรารีฟรี `soundfont-player` (+ ชุดเสียง MusyngKite) โหลด **acoustic_grand_piano / string_ensemble_1** เล่นเพลง 1 สดในเบราว์เซอร์ · โหลด ~2 วินาที/เครื่อง (verify ในหน้า). ทางเลือกไลบรารี: `soundfont-player`, `smplr`, หรือ `Tone.js Tone.Sampler` (Salamander Grand — เปียโนคุณภาพสูง).
- **ข้อแลกเดียว (ต้องบอก P'Aim ตรง ๆ):** เสียงจริง = **โหลดไฟล์เสียงก่อน** (เปียโน MusyngKite ~a few MB · โหลดครั้งแรกครั้งเดียวแล้ว cache). synth ปัจจุบัน = 0 download. → ต้องมี fallback เป็น synth ตอนออฟไลน์/เน็ตช้า (เดโมทำ fallback แล้ว) · หรือ bundle ชุดเสียงเล็ก ๆ ไปกับเว็บ.
- **ผลต่อ B104 architecture:** `scheduleNote` (ที่แยกไว้ให้ realtime+MP3 ใช้ร่วม) กลายเป็น "จุดสลับเครื่องดนตรี" — เพิ่มทางให้ route โน้ตไป sampler แทน oscillator ได้ทั้ง 2 ที่พร้อมกัน (ฟัง + MP3). voicing styles (§0) ทำงานเหมือนเดิม เพราะมันสร้าง "เหตุการณ์โน้ต" ไม่ผูกกับ timbre.
- **โบนัสที่ทำให้ว้าว:** melody = เปียโน + chord = สตริง พร้อมกัน = "จัดวงเล็ก ๆ" (เดโมรอบ 3 มีโหมด 🎹+🎻). นี่คือทิศทางที่ทำให้เว็บฟังเหมือนมีคนบรรเลงจริง.

**คำแนะนำ (SA):** เสียงจริง (sampled) คือ **การอัปเกรดความเพราะที่ใหญ่กว่าทุกอย่างใน §0-§2 รวมกัน** — เพราะเปลี่ยน "เนื้อเสียง" ทั้งหมด. แต่เป็น **งาน dev จริง** (โหลด/จัดการ sample + fallback + เลือกเครื่องใน UI + ต่อ MP3 export) ไม่ใช่ tweak. เสนอเป็น **ฟีเจอร์แยก (ต่อจาก voicing selector)**: "เลือกเสียงเครื่องดนตรี" (สังเคราะห์/เปียโน/สตริง/ผสม). ให้ P'Aim ฟังเดโมรอบ 3 ก่อนเคาะว่าจะลงทุนทำ.

### 🎼 อัปเดตรอบ 4 — เสนอเป็น "3 แบบบรรเลง" (curated presets) ไม่ใช่ปุ่มปรับดิบ ๆ
P'Aim (ในฐานะผู้ใช้) บอกชัด: **อยากได้ "แบบที่จัดมาแล้วให้เพราะ" ให้เลือก ไม่ใช่มานั่งปรับเครื่อง×สไตล์เอง** · และให้ SA (ผม) เป็นคน "เรียบเรียง" ตัดสินว่าอะไรเพราะ. **นี่คือ insight สำคัญของ productization:** ผู้ใช้ทั่วไป (คนในโบสถ์) ไม่ใช่ sound engineer — เขาต้องการ **ตัวเลือกบรรเลงสำเร็จรูปไม่กี่แบบ** ที่แต่ละแบบเพราะพร้อมใช้.

**สังเกตการเปลี่ยน scope จาก B104:** presets เล่น **ทำนองด้วยเครื่องจริง**ด้วย (ไม่ใช่แค่คอร์ด) — B104 เดิม melody = synth เสมอ. "เปียโนบรรเลง" ที่แท้จริงต้องให้ **ทำนองอยู่บนเปียโนด้วย**. ดังนั้นฟีเจอร์นี้ = "โหมดบรรเลง" ที่กำหนดทั้ง **เครื่องของทำนอง + เครื่องของคอร์ด + สไตล์คลอ** พร้อมกัน.

**3 แบบที่ SA จัดให้ (เดโมรอบ 4 · verify โหลด+เล่นได้ครบ):**
| # | preset | ทำนอง | คอร์ด/คลอ | ทำไมเพราะ |
|---|---|---|---|---|
| 1 | **แกรนด์เปียโนล้วน (สงบ)** | เปียโน | เปียโน · คอร์ดค้างเบา กังวานยาว (sustain) · ช้า (~64) | *น้อยแต่มาก* — Sacred Space, felt-piano, ใคร่ครวญ. เรียบสุด กินใจสุด (P'Aim ขอเพิ่ม) |
| 2 | **เปียโนบรรเลง (มือซ้ายไหล)** | เปียโน | เปียโน · **broken chord (arp)** | เอาเพลงเป็นหลัก · มือซ้ายไหลใต้ทำนอง ไม่ตอกเป็นก้อน = เหมือนคนเล่นจริง |
| 3 | **ไวโอลินคลอเปียโน** | **ไวโอลิน** (ลากยาว ร้องเพลง) | เปียโน arp เบา ๆ | คู่คลาสสิก — ไวโอลินสีทำนองเด่น เปียโนพยุง = หวาน สง่า |
| 4 | **เต็มวง (มีคอร์ดชัด)** | เปียโน | **สตริง pad ค้าง** (voice-led) | ได้ยินคอร์ด/ประสานชัด อุ่น เต็ม แบบนมัสการ |

> ทั้ง 4 ใช้ engine เดียวกัน (sampler + voice-leading + สไตล์คลอ §0) — preset = แค่ config `{melInst, chordInst, style, bpm}`. **default แนะนำ = "แกรนด์เปียโนล้วน (สงบ)"** — ตรงกับ CCM ร่วมสมัย (นุ่ม ลุ่มลึก น้อยแต่มาก) ที่ P'Aim ชี้ชัด · อีก 3 เป็นทางเลือกไล่ระดับความเต็ม.

**หลักการ CCM ร่วมสมัย (P'Aim ชี้ · SA เห็นด้วย):** เพลงคริสเตียนยุคนี้ = เรียบ เข้าถึงอารมณ์ สากล — ไม่ใช่ออร์แกนท่อ/ฮาร์ปโบราณดุดัน. หลักที่ใช้เลือกเครื่อง: (1) **เปิด-ปิดตามโครงเพลง** — verse = เปียโนเดี่ยวทุ้มนุ่ม (สงบ), chorus/ท้าย = สตริงลากยาวเอ่อล้นเข้าเสริม (ไม่ต้องมีกลอง); (2) **แบ่งย่านความถี่** — เบส = มือซ้ายเปียโน/เชลโล · กลาง = มือขวาเปียโน/วิโอลา · สูง = ไวโอลินประสาน (ระวังแหลมบาดหู); (3) **Less is more + Space** — ปล่อยเปียโนกังวานยาว ทิ้งช่องว่างให้ "Sacred Space". → **future preset "cinematic": เปียโน + ambient pad แผ่ว + สตริง con sordino** (อุ่น หม่น มีมิติ) · และ **dynamic ตามท่อน** (verse เบา → chorus เต็ม) เป็น enhancement ที่ทำได้เพราะเรารู้โครง section แล้ว.

**โทนเสียงที่ตรงใจ = "Felt Piano" (เปียโนบุผ้าสักหลาด · นุ่ม ทุ้ม ไม่แหลม):** soundfont GM ในเดโม (MusyngKite grand) สว่างไป — production ควรหา **sample โทนนุ่ม** (คีย์เวิร์ด: Felt/Soft/Intimate Piano · Chamber/Con-sordino Strings). แหล่งฟรีคุณภาพสูง: **Pianobook** (felt piano เพียบ), **Spitfire LABS** (Soft Piano/Strings), **MuseSounds** (Orchestral Tools · ผ่าน MuseScore4), **Polyphone** (.sf2). → งานเลือก/โฮสต์ sample โทนนุ่ม = task ย่อยของฟีเจอร์นี้ (ดู §รอบ 5 เรื่อง format).

**หลักการเรียบเรียง (ทำไมจับคู่แบบนี้):** (ก) **ทำนองต้องเด่นสุด** → ให้เครื่องที่ "ร้องเพลง" ได้ (ไวโอลินลากยาว / เปียโนชัด) · (ข) **คอร์ดต้องอยู่ใต้ ไม่แย่งซีน** → เปียโน broken-chord (โปร่ง มีช่องให้ทำนองหายใจ) หรือสตริง pad (นุ่ม ฟุ้ง อยู่หลัง) · (ค) **ไม่ซ้ำ timbre จนตัน** → ถ้าทำนอง+คอร์ดเป็นเปียโนทั้งคู่ ใช้จังหวะ (arp) แยกบทบาทมือซ้าย-ขวา; ถ้าอยากแยกชัดใช้คนละเครื่อง (ไวโอลิน+เปียโน / เปียโน+สตริง).

**คำแนะนำ (SA · ทิศทางสุดท้าย):** ทำ productization เป็น **"โหมดบรรเลง" 3-4 preset สำเร็จรูป** (แบบข้างบน) เป็นสิ่งที่ผู้ใช้เห็น · ซ่อนปุ่มปรับดิบ (เครื่อง×สไตล์×gain) ไว้เป็น "ขั้นสูง" (ถ้าจะมี). เบื้องหลัง = sampler + voicing engine เดียว. งาน dev: sampler + fallback + preset config + เล่นทำนองด้วยเครื่องจริง + ต่อ MP3 export. เป็นงาน **กลาง-ใหญ่** แต่ให้ผลลัพธ์ "เว็บฟังเหมือนมีคนบรรเลงจริง" — คุ้มมาก.

### 🏗️ อัปเดตรอบ 5 — สถาปัตยกรรม: 400 เพลง "เจนอัตโนมัติ" ยังไง (ตัดสินใจใหญ่ · ให้ PM คิดต้นทุน)
P'Aim ชี้โจทย์จริง: **"มีโน้ต 400+ เพลงแล้ว · ไม่ใช่นักทำเพลง · ไม่อยากทำทีละเพลง · อยากล็อกแม่แบบเสียงเพราะ แล้วให้ระบบเจนออกมาให้หมดอัตโนมัติ"**. มี 2 สถาปัตยกรรม — **เลือกให้ถูกคือหัวใจ:**

| | **A. Live sampler ในเบราว์เซอร์** (เดโมนี้ทำอยู่) | **B. Pre-render MP3 ล่วงหน้าทุกเพลง** (batch) |
|---|---|---|
| ทำงาน | โหลด sample ชุดเดียว → สังเคราะห์สดตอนกด | รันครั้งเดียว: ทุกเพลง → ไฟล์ MP3 เก็บไว้ (Python+FluidSynth+.sf2 / MuseScore Batch / **หรือ OfflineAudioContext ของเราเอง**) |
| **ทรานสโพส/เปลี่ยนคีย์สด** | ✅ ได้ (ขับด้วยโน้ต) | ❌ ไม่ได้ (ไฟล์ล็อกคีย์เดียว — ต้อง render ทุกคีย์ = ระเบิด) |
| **แก้เพลง/เพิ่มเพลง** | ✅ อัตโนมัติทันที (sheet=SSOT) | ❌ ต้อง re-render เพลงนั้นใหม่ทุกครั้งที่แก้ |
| คุณภาพ sample | จำกัดที่ browser (sample เล็ก-กลาง) | ✅ ใช้ library หนักระดับ studio ได้ (.sf2 ใหญ่, felt piano พรีเมียม) |
| โหลดฝั่ง user | sample ~a few MB ครั้งแรก/เครื่อง + CPU มือถือ | ✅ แค่สตรีม MP3 (เบา เล่นทันที) |
| งาน/ต้นทุน | dev เขียน sampler layer ครั้งเดียว | เขียน batch pipeline + storage 400×(preset×?) ไฟล์ |

**ข้อสังเกตสำคัญ (SA):** โจทย์ core ของ pleng = **แผ่นเพลง SSOT + ทรานสโพสสด + ผู้ใช้แก้เพลงได้** → **แนวทาง A (live sampler) เข้ากับ DNA ของเว็บที่สุด** เพราะ B ทำให้ทรานสโพส/แก้เพลงพัง (จุดขายหลักของเรา). **และเรามี MP3 export อยู่แล้ว** (`audioExport.js` บน OfflineAudioContext ใช้ `scheduleNote` ตัวเดียวกับปุ่มฟัง) → แค่ route ผ่าน sampler เดียวกัน จะได้ทั้ง **เล่นสด (เสียงจริง) + ปุ่มโหลด MP3 (เสียงจริง)** จาก engine เดียว **ไม่ต้องมี DAW/MuseScore/pipeline แยกเลย**. batch MP3 (B) เก็บเป็น fallback เฉพาะถ้า CPU มือถือรุ่นเล็กไม่ไหว หรืออยากได้ felt-piano พรีเมียมที่หนักเกินโหลดสด.

**สรุปทิศ (SA):** ทำ **A — live sampler + preset บรรเลง + ต่อ MP3 export ให้ใช้ sampler เดียวกัน**. เลือก sample โทน felt/warm ที่ "เบาพอโหลดในเว็บ แต่เพราะ" (Pianobook/LABS/Polyphone/สกัดจาก .sf2). นี่ทำให้ 400 เพลง "เพราะอัตโนมัติทั้งหมด" โดยไม่ต้องแตะทีละเพลง — ตรงโจทย์ P'Aim — และยังทรานสโพส/แก้ได้.

> ⚠️ **scope creep (ต้อง PM ตัดสิน):** B106 เริ่มจาก "คอร์ดดังไป + voicing เพราะขึ้น" (งานเล็ก บน synth) → ตอนนี้บานเป็น **"โหมดบรรเลงเสียงจริง (sampler) + preset + felt-piano sourcing + MP3 real-instrument"** = ฟีเจอร์ผลิตภัณฑ์ใหญ่.

### 🎯 อัปเดตรอบ 6 — humanization (auto-arranger 3 ชั้น) + Felt vs Grand + **P'Aim เคาะ: เอาเต็มระบบ**

**ตัวเรียบเรียงอัตโนมัติ = 3 ชั้นกฎกลาง (deterministic + สุ่มคุมได้ · อ่านโครงเพลงจริง · ใช้ทุกเพลง ไม่ทำทีละเพลง):**
1. **โน้ต — voice-leading** (§0/§2): เลือกเสียงคอร์ดให้ลื่น ไม่ทับทำนอง.
2. **กดหนัก-เบา — dynamics** (แก้ "กดแข็ง/ทื่อ"): velocity ต่อโน้ต = **metric accent** (จังหวะตกหนัก · บีต 3 กลาง · จังหวะยก/เศษ เบา) × **melodic contour** (ไต่ขึ้น/โน้ตยอด หนักขึ้น · ลง/โน้ตยาวจบวรรค เบาลง) × **jitter เล็กน้อย**. เดโมวัดได้ velocity กระจาย ×0.66–1.14.
3. **ลูกเล่น — embellishments** (สมจริง "ไม่เหมือนทุกครั้ง"): กฎสุ่มโอกาสเกิด เลือกโน้ตปลอดภัย (chord tone / chromatic approach) — เปียโน arp: สลับลวดลายไล่คอร์ด, โน้ตนำเข้าเบส, ประกายอ็อกเทฟสูง, เติมช่องว่างคอร์ดยาว · สตริง: สเวลล์อ็อกเทฟบางคอร์ด. ~10/40 คอร์ดเท่านั้น (คง less-is-more) · 2 รอบเล่นต่างกันจริง.
> ทั้ง 3 ชั้น + section-dynamics (verse เบา/chorus เต็ม) = "auto-arranger" ที่ปรุง 400 เพลงให้เพราะเท่ากันอัตโนมัติ.

**Felt vs Grand (P'Aim ถาม):** **Grand = default** — งานเราให้คน**เรียน+ร้องตาม** → ต้องการหัวเสียงชัด ระดับเสียงคม (Felt คลุมจม จับทำนองยากกว่า + เบา) · **Felt = โทนเสริมสำหรับ preset สงบ/ใคร่ครวญ (เดี่ยว เว้นวรรค)**. แต่ง Grand ให้ "นุ่มแบบ felt" บางส่วนได้ด้วย dynamics เบา + low-pass โดยไม่เสียความชัด.

**🟢 P'Aim เคาะ (ผ่านการฟังเดโมเอง): เอาแบบเต็มระบบ ("full")** — ทำ **โหมดบรรเลงเสียงจริง** เต็มรูป (ไม่ใช่แค่แก้ gain บน synth). → SA แนะนำ PM **เปิด task ใหม่ "โหมดบรรเลงเสียงจริง"** (งานกลาง-ใหญ่: sample hosting CC + preset engine + auto-arranger 3 ชั้น + Grand default/Felt option + ต่อ MP3 export). "แก้คอร์ดดังไป (§1) + voicing (§2)" ถูกกลืนรวมในฟีเจอร์นี้แล้ว.

## 1. Gain / mix — คอร์ดดังไปจริงไหม · ควรตั้งเท่าไร

### 1a. ทำไมถึงรู้สึกดัง (ทั้งที่ตัวเลขดูเบากว่า)

`scheduleNote` วันนี้: ทำนอง peak **0.35**, คอร์ดแต่ละเสียง peak **0.12** (`chordGain`). ดูเหมือนคอร์ดเบากว่า 3 เท่า — แต่:

| ปัจจัย | ผล |
|---|---|
| **คอร์ด = 4-5 เสียงพร้อมกัน** | เสียงหลายตัวซ้อนดังรวมกัน ≈ 0.12 × √4 = **0.24** → เทียบทำนอง 0.35 แค่ **−3.3 dB** (5 เสียง = −2.3 dB) |
| **คอร์ดค้างยาว · ทำนองสั้น-มีช่องว่าง** | ทำนองหยุดก่อน 0.07s ทุกโน้ต + มีพัก · คอร์ดดังต่อเนื่องทั้งห้อง → **พลังงานเฉลี่ยตามเวลา**ของคอร์ดมากกว่าทำนอง หูเลยได้ยินคอร์ดเด่น |
| **triangle ย่านต่ำ ไม่กรอง** | ฮาร์มอนิกคี่ของ triangle ที่ C2/C3 สร้างเสียง "หึ่ง" ค้าง กลบความชัดของทำนอง |

→ **"คอร์ดดังไป" คือของจริง** ไม่ใช่แค่ความรู้สึก. (คำนวณ: `docs/reports/b106-sa-chord-quality.md` §gain-math)

### 1b. ค่าที่แนะนำ

เป้า: **คอร์ดรวม ~−9 dB ใต้ทำนอง** (ทำนองนำชัด คอร์ดคลอใต้) — ตัวเลขเริ่มต้นให้ dev จูนด้วยหูต่อ:

| พารามิเตอร์ | เดิม | แนะนำ | เหตุผล |
|---|---|---|---|
| ทำนอง peak | 0.35 | **0.35 (คงเดิม)** | ทำนองเป็นตัวนำ ไม่แตะ |
| คอร์ด — เสียงใน (3/5/7) | 0.12 | **~0.055** | 3 เสียง √-sum ≈ 0.095 |
| คอร์ด — เบส (ราก) | 0.12 | **~0.08** | เบสควรอุ้มมากกว่าเสียงใน (foundation) |
| **บัสคอร์ด: low-pass** | — | **~1.9 kHz, Q 0.7** | ตัดปลาย triangle ที่ "หึ่ง" → คลอนุ่ม |
| **บัสคอร์ด: compressor** | — | **thresh −20 dB · ratio 3:1 · knee 14** | กันคอร์ดพุ่งตอนเฟสตรงกัน |
| envelope คอร์ด | attack 0.04, plateau | **attack 0.05-0.06 → decay ลง ~0.7** | คลอแล้ว "ยุบ" นิด ให้ทำนองนั่งข้างบน ไม่เป็นกำแพงนิ่ง |

รวมแล้วคอร์ด stack ≈ RMS 0.12 = **−9 dB** ใต้ทำนอง (คำนวณยืนยันแล้ว). **สำคัญเชิงสถาปัตย์:** วันนี้แต่ละเสียงคอร์ดต่อตรงเข้า `ctx.destination`. ให้สร้าง **บัสคอร์ด 1 ตัว** (`GainNode → BiquadFilter(lowpass) → DynamicsCompressor → destination`) แล้วต่อทุกเสียงคอร์ดเข้าบัสนี้ — ได้ทั้ง low-pass, compressor และปุ่มปรับ "ระดับคอร์ด" รวมจุดเดียว (ต่อ MP3 export ด้วย).

## 2. Voicing / accompaniment — ทำให้ไพเราะขึ้น (4 ทางเลือก)

> **หลักที่ยึด (สืบจาก B104): sheet = SSOT.** ทุกทางเลือกใช้ "โน้ตของคอร์ดตามที่ชื่อคอร์ดบอก" เท่านั้น — **ไม่เติม tension (9th/6th) ที่แผ่นไม่ได้สั่ง** เพราะอาจชนทำนองและผิดหลัก "ได้ยินตามแผ่น". ความไพเราะมาจาก **การเรียงเสียง** ไม่ใช่การเติมโน้ต. (การเติม tension = future flag "lush" · §5.)

ทั้ง 4 ต่อยอด `chordVoicing()` / `buildChordVoice()` เดิม (แยก "เลือกโน้ต" ออกจาก "ตีเมื่อไร" ไว้แล้วตั้งแต่ B104).

### ตัวเลือก A — Polish (แก้มิกซ์+ทะเบียน · ยังเป็น block ค้าง)
**ทฤษฎี:** เก็บ block triad ค้างเดิม แต่ (1) **ตัดรากซ้ำใน block** (เบสอุ้มรากแล้ว · block = 3+5+7 พอ → บางลง ใสขึ้น) (2) **บีบเสียงบนให้อยู่หน้าต่างคงที่** (เช่น MIDI 52-63 = E3-D#4) ทุกคอร์ด → คอร์ดรากสูง (A/B) ไม่ไต่ทับทำนองอีก (3) ผ่านบัส low-pass+compressor จาก §1.
**โปรแกรม:** `chordVoicing` normalize register — วาง pitch-class ของ 3/5/7 ลงหน้าต่าง `[lo,hi]` (โมดูโล 12) · เบส = ราก ย่าน 40-47.
**ข้อดี:** เปลี่ยนน้อยสุด · เสี่ยงต่ำสุด · แก้ "ดังไป+ทับทำนอง" ครบ · ไม่ต้องรู้จังหวะ.
**ข้อเสีย:** ยังเป็น pad ค้างนิ่ง (drone) · เสียงบนยัง**กระโดด**ระหว่างคอร์ด (ราก-position เสมอ) → "สะอาด" แต่ยังไม่ "ไพเราะลื่น".

### ★ ตัวเลือก B — Voice-leading + inversions (คอร์ดขยับน้อย · นุ่มลื่น) — **แนะนำเป็น default ใหม่**
**ทฤษฎี:** หัวใจของ "คอร์ดคลอเพราะ" คือ **เสียงบนขยับน้อยที่สุด** — โน้ตร่วม (common tone) ค้างไว้ ตัวที่เหลือเดินทีละ 1-2 เสียง แทนที่จะยกทั้งก้อนขึ้นลง. นี่คือสิ่งที่นักเปียโน/ออร์แกนทำโดยสัญชาตญาณ และเป็นตัวแยก "คลอมือโปร" ออกจาก "ตอกคอร์ดจากตาราง". เบสยังเป็นราก (ย่านต่ำ) แยกชัด.
พิสูจน์: บนโปรเกรสชัน C-G-Am-F-C-F-G7-C เสียงบนขยับเฉลี่ย **~4 semitone/คอร์ด** และอยู่ในย่าน E3-E4 ตลอด (ไม่เคยทับทำนอง) — เทียบ block เดิมที่กระโดดและไต่ถึง E4/F#4.
**โปรแกรม:** ส่ง `prevVoicing` เข้าไปตอนสร้างคอร์ดถัดไป (loop ใน `buildChordVoice` เป็น sequential อยู่แล้ว → ง่าย). แต่ละ pitch-class ของ 3/5/7 เลือก octave (ในหน้าต่าง 48-67) ที่**ใกล้ centroid ของคอร์ดก่อนหน้าที่สุด**. Pure · เทส headless ได้.
**ข้อดี:** **ไพเราะต่อความพยายามสูงสุด** · ไม่ต้องรู้จังหวะ (ยังค้าง block) · เสี่ยงชนทำนองต่ำ (คุมย่าน) · ฟังเหมือน string/organ pad อุ่น ๆ.
**ข้อเสีย:** โลจิกเพิ่ม ~30-40 บรรทัด · ต้อง thread state คอร์ดก่อนหน้า (แต่ง่ายเพราะ loop เรียงอยู่แล้ว).

### ตัวเลือก C — Arpeggio / broken chord (ไล่เสียง · โปร่ง มีจังหวะ) — **แนะนำเป็น style ที่ 2 (v2 เลือกได้)**
**ทฤษฎี:** แทนตีค้างเป็นก้อน → กระจายโน้ตคอร์ดทีละตัวตามจังหวะ (เบสลงบีตแรก แล้วไล่ 5-3-5 แบบ fingerpick/Alberti เบา ๆ). เพราะโน้ต**สั้นและเหลื่อมกัน** จึงมีช่องว่างให้ทำนอง "หายใจ" → บังทำนองน้อยกว่า block → มักเป็นแบบที่ **"เพราะที่สุด" สำหรับเพลงช้า/นมัสการ**.
**โปรแกรม:** `buildChordVoice` ต้องรู้ **จังหวะ** (beats/bar จาก `content.time`) + ช่วง beats ของ event → ปล่อยหลายโน้ตสั้นตาม pattern grid. schedule เยอะขึ้น.
**ข้อดี:** มีชีวิต · โปร่ง · unmask ทำนองในตัว · เพราะมากกับเพลงช้า.
**ข้อเสีย:** **ผูกกับจังหวะ** — เพลงที่ทำนอง syncopate อาจตีกับ pattern · โค้ดมากสุดในกลุ่ม · ควรเป็น **ตัวเลือก opt-in ไม่ใช่ default** (เผื่อเพลงเร็ว/จังหวะแปลก).

### ตัวเลือก D — Split-hands: root-fifth bass + inner pad (สไตล์เปียโนโบสถ์)
**ทฤษฎี:** เลียนมือเปียโนจริง — มือซ้าย = ราก (บีต 1) + คู่ 5 (บีต 3) ให้ชีพจรฮาร์โมนี · มือขวา = inner triad (3/5/7 ไม่มีราก) voice-led ค้าง (= B). แยกทะเบียนสะอาด ทำนองนั่งบนสุด.
**ข้อดี:** ใกล้ "มือซ้ายคลอ" จริงที่สุด · เบสมั่นคง + pad ลื่น.
**ข้อเสีย:** ซับซ้อนสุด · ผูกจังหวะ (เบสมีจังหวะ) · เกินจำเป็นสำหรับ v1 → เก็บเป็น future "piano" style.

## 4. วิธี implement (ต่อยอดโค้ด B104 จริง)

ทุกอย่างอยู่ใน `src/lib/` ที่ B104 วางไว้ — ไม่แตะ model/DB/UI (ยกเว้นถ้าทำ v2 selector).

### 4a. บัสเสียงคอร์ด (แก้ "ดังไป") — `midi.js` `playSong` + `audioExport.js`
```js
// สร้างครั้งเดียวต่อการเล่น แล้วส่งเป็น destination ให้ scheduleNote ของคอร์ด
function makeChordBus(ctx, dest, chordGain) {
  const g = ctx.createGain();  g.gain.value = chordGain          // ปุ่มระดับคอร์ดรวม
  const lp = ctx.createBiquadFilter(); lp.type='lowpass'; lp.frequency.value=1900; lp.Q.value=0.7
  const comp = ctx.createDynamicsCompressor()
  comp.threshold.value=-20; comp.knee.value=14; comp.ratio.value=3; comp.attack.value=0.02; comp.release.value=0.18
  g.connect(lp).connect(comp).connect(dest)
  return g
}
```
- ใน `playSong`: คอร์ด `scheduleNote(ctx, chordBus, m, …)` แทน `ctx.destination` · เบสส่ง peak สูงกว่าเสียงใน.
- `scheduleNote`: เพิ่มพารามิเตอร์ envelope decay (attack → decay ลง ~0.7 → sustain) สำหรับคอร์ด (ทำนองคงเดิม). ปัจจุบันมี `peak`/`attack` แล้ว → เพิ่ม `decayTo`.
  - **⚠️ กัน click/ป๊อป (สำคัญ):** envelope ต้อง **ต่อเนื่อง** เสมอ — attack ramp → (decay ramp) → **hold ที่ระดับ sustain จริง** → release ramp ลง 0. **ห้าม hard-jump gain ไป 0** (= เสียงติ๊กทุกโน้ต). โค้ด B104 ปัจจุบันทำถูกแล้ว (`setValueAtTime(peak,…)` + release ramp 50ms ที่บรรทัด `scheduleNote`) → **B104 บน live ไม่มีเสียงติ๊ก**. ตอนเพิ่ม `decayTo` ให้คง release ramp ไว้ (≥~20-30ms) และ setValueAtTime ที่ระดับ sustain ที่ถูกต้อง — อย่าเผลอส่งค่าปัจจุบัน (0). (บทเรียนจากเดโม: เดโมรอบแรกส่ง `g.gain.value`=0 → คลิกทุกจังหวะ · แก้แล้วในเดโมรอบนี้.)
- gain: แยก `chordBassGain` (~0.08) กับ `chordInnerGain` (~0.055) หรือคูณจาก `chordGain` เดียว (bass ×1.4, inner ×1.0). แทนที่ `chordGain=0.12` เดิม.

### 4b. Voice-leading (default ใหม่ · ตัวเลือก B) — `midi.js`
`chordVoicing(chordStr)` วันนี้ไม่มี state. เปลี่ยนเป็นรับคอร์ดก่อนหน้า และแยกเบส/เสียงบน:
```js
const UP_LO = 48, UP_HI = 67                       // C3..G4 หน้าต่างเสียงบน
function nearestOctave(pc, target) {                // pitch-class -> midi ใกล้ target สุด
  let best = UP_LO + ((pc - UP_LO) % 12 + 12) % 12
  for (let x = best; x <= UP_HI; x += 12) if (Math.abs(x-target) < Math.abs(best-target)) best = x
  return best
}
// คืน { bass, up:[…] }; prevUp = เสียงบนของคอร์ดก่อนหน้า (null = คอร์ดแรก)
export function chordVoicing(chordStr, prevUp = null) {
  const p = parseChord(chordStr || ''); if (!p) return { bass: null, up: [] }
  const pcs = chordToIntervals(p.suffix).slice(1).map(iv => (p.rootIndex + iv) % 12)  // 3/5/(7)
  const anchor = prevUp && prevUp.length ? prevUp.reduce((a,b)=>a+b,0)/prevUp.length : 58
  const up = pcs.map(pc => nearestOctave(pc, anchor)).sort((a,b)=>a-b)
  const bass = 40 + ((p.rootIndex - 4) % 12 + 12) % 12       // ราก ย่าน E2..B2 (40-47)
  return { bass, up }
}
```
- `buildChordVoice(notes)`: เก็บ `prevUp` ข้าม event → ส่งเข้า `chordVoicing` ตัวถัดไป · `midiSet = [bass, ...up]`.
- **หมายเหตุอัลกอริทึม (สำหรับ production ให้ดีกว่าเดโม):** `nearestOctave` แบบต่อเสียงอาจให้ voice cross เล็กน้อย — ถ้าอยาก smooth จริง ให้ score ทั้ง voicing (ผลรวม |Δ| เทียบ prevUp ทุกตัว รวม common-tone bonus) แล้วเลือก min. เดโมใช้แบบ per-note ก็ลื่นพอฟังต่างชัดแล้ว.

### 4c. Voicing-style selector (v2 · palette §0) — `midi.js` + selector
สถาปัตย์: แยก 3 ชั้นให้ชัด แล้ว style = การ "articulate" ชั้นโน้ต voice-led —
- **ชั้นโน้ต** (§4b `chordVoicing`) คืน `{bass, up}` — ใช้ร่วมทุก style.
- `buildChordVoice(notes, { style, beatsPerBar })` — `style` = `'sustain' | 'arp' | 'roll' | 'pad' | 'waltz'`; อ่าน `beatsPerBar` จาก `content.time` (จำเป็นเฉพาะ arp/waltz).
  - **sustain:** 1 event/คอร์ด ค้าง (เหมือน B104 แต่โน้ต voice-led).
  - **arp:** แตกเป็น hit สั้นตามบีต (เบส→5→3→5).
  - **roll:** โน้ตชุดเดียวแต่ offset onset ทีละ ~30ms (ล่าง→บน) — `scheduleNote` รับ `startT` เหลื่อมได้อยู่แล้ว.
  - **pad:** ค้าง แต่ **2 oscillator เพี้ยน ±6 cents (chorus)** + attack ช้า (~0.35s) — ต้องเพิ่ม `scheduleNote` variant หรือ flag `voices:2/detune/slowAttack`.
  - **waltz:** เบสบีต1 + คอร์ดย่ำสั้นบีต 2-3-4.
- `playSong`/export: schedule ตาม hit ที่ style คืน. **UI:** ตัวเลือก style (segmented/เมนู) วางคู่ selector 3 โหมดเสียงเดิม · localStorage จำค่า.
- **timbre note:** `scheduleNote` วันนี้ = triangle เดี่ยว. เพิ่ม option **dual-osc detuned (chorus)** + **attack ช้า** เพื่อรองรับ 'pad' — คันโยกความเพราะที่แรงสุด (§0). reverb (ConvolverNode) = future.
