# DS — Edit → completion flow (BI-007)

**คู่กับ:** bug-intake BI-007 (พี่เปา: "แก้เพลงเสร็จแต่ทำได้แค่บันทึกร่าง · ไม่มีทางเผยแพร่ · แย่กว่า v1")
**สถานะ:** design spec — ยังไม่ build · รอ PM ส่ง P'Aim เคาะ เอา/ไม่เอา
**Scope:** โฟลว์ "แก้ → เก็บ → ส่ง → อนุมัติ → เผยแพร่" ครบทุก role · เดลตาบน `EditorMode.vue` จริง (ไม่ใช่ mockup ทิ้ง)

> P'Aim ยกทั้งโฟลว์ให้ทีมออกแบบระดับโลก ("ผมไม่คิดแล้ว"). ไอเดียดิบเดิม ("ปุ่ม Publish โชว์เสมอ · ไม่มีสิทธิ์ = disabled + บอกเหตุผล") = **หนึ่ง input** ไม่ใช่ spec ตายตัว — spec นี้ยกระดับให้เป็น "ปุ่มจบงานที่ปรับตาม role + แถบสถานะ you-are-here" แทน disabled dead-button.

## 0. TL;DR (F60 — อ่าน 60 วิ เข้าใจทั้งหมด)

**เพดานสิทธิ์จริง (verify แล้ว):** เผยแพร่ขึ้นคลัง = **approver เท่านั้น** (RLS, ไม่ใช่ "แค่ล็อกอิน"). editor เพดานอยู่ที่ **"ส่งตรวจ"** · anon เก็บเข้าระบบไม่ได้เลย (ทำได้แค่ไฟล์ตัวเอง + อีเมลขอให้ทีมนำขึ้น).

**ทำไมรู้สึก "แย่กว่า v1":** v1 = ใครล็อกอินก็เขียนลง `songs` ตรง = **กด 1 ที ขึ้นเว็บทันที**. v2 เพิ่มชั้น draft/review (ถูกต้อง — ได้ role + audit) แต่ **ไม่มีจังหวะ "จบแล้ว = ขึ้นแล้ว" ที่รู้สึกได้** → editor กด "ส่งตรวจ" แล้วเงียบ ไม่เห็นว่าอยู่ตรงไหน ใครรับต่อ เมื่อไรขึ้น = ตัน.

**5 ช่องโหว่ที่ทำให้ตัน (ยืนยันในโค้ด §3):** anon ไม่มีปุ่มจบงานเลย · สถานะร่าง (ร่าง/รอตรวจ/ถูกส่งกลับ) เป็นข้อความชั่วคราวหายไปกับ dock ตอนสกรอลล์/รีโหลด · 2 ปุ่ม (บันทึกร่าง vs ส่งตรวจ) แข่งกันไม่รู้อันไหน "จบ" · ส่งตรวจแล้วไม่มีหน้ายืนยัน+ขั้นถัดไป · ไม่มี "เสร็จ" อันเดียวที่ทำสิ่งที่ถูกต้องตาม role.

**ข้อเสนอหลัก (world-class):**
1. **ปุ่มจบงานปุ่มเดียว ปรับตาม role** (โชว์เสมอทุก role รวม anon) — ไม่ใช่ disabled dead-button.
2. **แถบสถานะ you-are-here** ติดบนพื้นที่แก้ (stepper) บอก "ตอนนี้อยู่ไหน → ขั้นต่อไปคืออะไร ใครทำ".
3. **auto-save ร่าง** (debounced) → เลิกปัญหา 2 ปุ่มแข่งกัน + งานไม่หาย (Google-Docs pattern).
4. **หน้ายืนยันหลังส่ง** — "ส่งแล้ว ทีมผู้ตรวจรับไปแล้ว · ติดตามได้ที่ งานของฉัน".

## 2. "เสร็จ" (Done) ตอนนี้ทำอะไรจริง

**ไม่มีปุ่ม "เสร็จ" แยกในตัวแก้.** การ "จบ" ปัจจุบัน = สลับโหมด (ดู/แผ่นเพลง/แก้) บน shell — เป็น `v-show` ไม่ unmount (`Studio.vue:400-407`) → ออกจากโหมดแก้ได้โดยไม่มีขั้น "จบงาน" ที่ชัด. มี guard กันงานหายตอนออกจาก route (`EditorMode.vue:1951-1954` `onBeforeRouteLeave` + `beforeunload`) แต่การสลับ "โหมด" ภายใน Studio ไม่เข้า guard นั้น. → **ยืนยันสมมุติฐานโจทย์:** ไม่มี "เสร็จ" ที่พาไปสู่การเผยแพร่ · การจบ = เดินออกเฉยๆ.

## 3. สิ่งที่ "มีแล้ว" vs "ช่องโหว่" (delta — ไม่รื้อของดี)

ตัวแก้ปัจจุบัน (`EditorMode.vue`) ทำมาดีหลายจุดแล้ว — spec นี้ต่อยอด ไม่ทิ้ง:

### มีแล้ว (คงไว้ · cite)
- ปุ่ม prime ปรับตาม role: editor→`ส่งตรวจ` · approver→`เผยแพร่`/`เผยแพร่ทับ` · reviewing→`อนุมัติร่าง` (`EditorMode.vue:2208-2222` `saveLabel`/`saveName`, WCAG 3.2.4/2.4.6/3.3.2 มีคอมเมนต์กำกับ)
- `primaryAction()` แยกเส้นถูก role + ยืนยันก่อนเผยแพร่ทับร่างที่รอตรวจ (`:2175-2189`, อ้าง HIG Alerts / M3 Dialogs)
- banner "มีร่างรอตรวจของเพลงนี้" (`pending-alert`, `:3135-3146`) + banner "กำลังตรวจร่างของ X" (`review-banner`, `:3149-3157`) — inline, aria-live, ไม่ใช่ toast (มีคอมเมนต์อ้าง HIG Feedback)
- แผงร่าง/คิวรอตรวจ พร้อม status chip + ลบร่าง (`:3849-3870`, `STATUS_TH` `:2275`)
- ปุ่ม `บันทึกร่าง` แยก (`:2265`) · migrate-note จาก v1 (`:3162-3169`)

## 4. โฟลว์เป้าหมาย — Role × State matrix (you-are-here → next)

**หลักการ:** ทุก role มี **ปุ่มจบงาน (Primary Finish) หนึ่งปุ่ม โชว์เสมอ** ที่ทำ "สิ่งที่ดีที่สุดที่สิทธิ์ทำได้" — ไม่ใช่ disabled dead-button. เหตุผลที่เผยแพร่ตรงไม่ได้ = อธิบาย inline ตรงจุด (Material: disabled + reason ใช้เฉพาะกรณีที่ gated จริง เช่น approver ที่มีร่างคนอื่นรอ).

### 4.1 State machine (ต่อ 1 เพลง/ร่าง)
```
        (anon)                         (editor)                    (approver)
แก้ ──► [ไฟล์ตัวเอง JSON] ──อีเมล──►  ┐
แก้ ──► ร่าง ──ส่งตรวจ──► รอตรวจ ─────┼──► [approver review] ──อนุมัติ──► เผยแพร่แล้ว (ขึ้นคลัง)
                          รอตรวจ ──ตีกลับ──► ถูกส่งกลับ ──แก้/ส่งใหม่──► รอตรวจ
แก้ (approver) ─────────────────────────────────เผยแพร่──────────────► เผยแพร่แล้ว
```

### 4.2 Matrix

| Role \ สถานะเพลง | Primary Finish (โชว์เสมอ) | Secondary | แถบ you-are-here | ขั้นต่อไปที่บอกผู้ใช้ |
|---|---|---|---|---|
| **anon** — แก้อยู่ | **"ส่งให้ทีมนำขึ้นคลัง"** → เปิด flow: ดาวน์โหลด JSON → อีเมล pleng@phrakham.life (WT-C DS-C03) | "ดาวน์โหลด JSON" (เก็บงาน) · ลิงก์ "ทีมมีบัญชี? เข้าสู่ระบบ" | ป้าย: *"งานนี้เก็บในเครื่องคุณ — ส่งให้ทีมนำขึ้นคลังได้"* | "① ดาวน์โหลด ② แนบอีเมลถึงทีม ③ ทีมตรวจแล้วนำขึ้น" |
| **editor** — ร่างใหม่/แก้อยู่ | **"ส่งตรวจ"** (prime) | "เก็บร่างไว้ก่อน" (auto-save ทำแล้ว → ปุ่มนี้เหลือเป็น manual/สำรอง) | ป้าย: *"ร่าง · เก็บอัตโนมัติแล้ว"* | "พร้อมแล้วกด ส่งตรวจ → ทีมผู้อนุมัติจะรับไปพิจารณา" |
| **editor** — รอตรวจ (ส่งแล้ว) | **"ดูสถานะ / ถอนกลับมาแก้"** | — | ป้าย status เด่น: *"⏳ รอตรวจ — ส่งเมื่อ {เวลา}"* | "ทีมผู้อนุมัติกำลังพิจารณา · จะแจ้งเมื่อขึ้นคลัง/ส่งกลับ" |
| **editor** — ถูกส่งกลับ | **"แก้แล้วส่งใหม่"** | — | ป้าย: *"↩ ถูกส่งกลับ: {comment}"* (คงบนพื้นผิว) | "แก้ตามคอมเมนต์ → ส่งตรวจอีกครั้ง" |
| **editor** — อนุมัติแล้ว | (เพลงขึ้นคลังแล้ว) | "แก้ต่อ (สร้างร่างใหม่)" | ป้าย: *"✅ ขึ้นคลังแล้ว"* | "อยู่บนเว็บแล้ว · แก้ต่อได้เป็นร่างใหม่" |
| **approver** — แก้เพลง | **"เผยแพร่"** / **"เผยแพร่ทับ"** (มีอยู่แล้ว) | "เก็บร่าง" | ป้าย: *"แก้ฉบับเผยแพร่ / ร่าง"* | "กด เผยแพร่ = ขึ้นคลังทันที" |
| **approver** — มีร่างคนอื่นรอตรวจของเพลงนี้ | **"⚠️ เผยแพร่ทับ"** + banner (มีแล้ว `:3135`) | "ดูร่างของ X" | banner pending-alert (มีแล้ว) | "ตรวจร่างของ X ก่อน หรือเผยแพร่ทับ (ร่างค้างรอ)" |
| **approver** — กำลังตรวจร่างคนอื่น | **"อนุมัติและเผยแพร่"** (มีแล้ว `:3153`) | "↩ ส่งกลับให้แก้" + ช่องคอมเมนต์ | review-banner (มีแล้ว) | "อนุมัติ = ขึ้นคลัง · ส่งกลับ = ผู้เขียนแก้ต่อ" |

> **จุดสำคัญ:** editor ไม่มีวัน "เผยแพร่" เอง (RLS). อย่าโชว์ปุ่มเผยแพร่แบบ disabled ให้ editor — มันสื่อผิดว่า "เดี๋ยวก็กดได้". เพดานของ editor คือ **ส่งตรวจ** และนั่นคือ "จบงาน" ของเขา — ต้องทำให้รู้สึกว่าเป็นการจบที่สมบูรณ์ (ยืนยัน + ติดตามได้) ไม่ใช่ครึ่งทาง.

## 5. เดลตาบนโค้ดจริง (dev ทำต่อได้ตรง — ไม่ mockup ทิ้ง)

### D-A · แถบสถานะ you-are-here (แก้ G2, G4) — **แกนหลัก**
- คอมโพเนนต์ใหม่เล็ก ๆ `CompletionStatus.vue` (หรือ block ในเทมเพลต `EditorMode.vue` เหนือ `edhead` `:3174`) — **persistent, inline, ไม่ผูกกับ dock**.
- แสดง **stepper แนวนอน**: `แก้ ─ เก็บร่าง ─ ส่งตรวจ ─ รออนุมัติ ─ เผยแพร่แล้ว` ไฮไลต์ขั้นปัจจุบันจาก `openDraft?.status` / `editingId` / `isApprover`.
- ใต้ stepper: 1 บรรทัด "ขั้นต่อไป" (จากคอลัมน์สุดท้าย §4.2) + เวลา (`updated_at`).
- ดึง state จาก getter ที่มีแล้ว: `openDraft`, `openPendingDraft`, `pendingForThisSong`, `reviewingDraft` (`:2941` expose). ถูกส่งกลับ = `openDraft.status==='rejected'` + `review_comment` (คงบนพื้นผิว แทนที่จะเป็น `saveMsg` วูบ `:1568`).
- **WCAG:** `role="status"` `aria-live="polite"` (มี precedent ในไฟล์ `:3135`). stepper ปัจจุบันใช้ `aria-current="step"`.

### D-B · ปุ่มจบงานสำหรับ anon (แก้ G1)
- ใน `editItems` (`:2254`): เพิ่มรายการ prime สำหรับ anon — `{ id:'finish-anon', prime:true, hidden: loggedIn.value, label:'ส่งให้ทีม', run: openSubmitFlow }`. (แทนที่จะให้ dock ว่างเปล่า.)
- `openSubmitFlow()` = การ์ด/ชีตอธิบาย 3 ขั้น + ปุ่ม "ดาวน์โหลด JSON" (มี `ExportTool`/WT-C อยู่แล้ว) + ปุ่ม mailto pre-filled (WT-C `DS-C03-email-submit`). ไม่สร้าง backend ใหม่.
- ลิงก์รอง "ทีมมีบัญชี? เข้าสู่ระบบ" → เปิด ProfileTool/navbar login.
- **หลีกเลี่ยง** disabled publish button ให้ anon (สื่อผิด + WCAG ปุ่ม disabled ไม่บอกเหตุ) — ใช้ปุ่ม enabled ที่พาไปเส้นทางจริงแทน.

### D-C · ลดความกำกวม 2 ปุ่ม (แก้ G3) — auto-save
- เพิ่ม **auto-save ร่าง** (debounced ~2–3s หลังหยุดพิมพ์) สำหรับ editor+ ที่ล็อกอิน โดยใช้ `isDirty`/`markClean` + `saveDraft('draft')` ที่มีแล้ว (`:1940-1943`, `:1658`). สถานะ "เก็บอัตโนมัติแล้ว/กำลังเก็บ…" โชว์ในแถบ D-A.
- เมื่อมี auto-save: `บันทึกร่าง` (`:2265`) ลดบทเป็น secondary เงียบ (หรือย้ายเข้า ⚙) → เหลือ **prime เดียว = "ส่งตรวจ"** ที่หมายถึง "จบงาน/ส่งต่อ" ชัดเจน.
- ผลลัพธ์: ตรงกับ mental model "แก้เสร็จ = กดปุ่มเด่นปุ่มเดียว" (Google Docs: งานไม่หาย, ปุ่มหลัก = share/submit ไม่ใช่ save).

### D-D · หน้ายืนยันหลังส่งตรวจ (แก้ G4)
- หลัง `saveDraft('pending')` สำเร็จ (`:1596,1614`): แทน `saveMsg` วูบ → การ์ด inline (dismissible) "📨 ส่งตรวจแล้ว — ทีมผู้อนุมัติจะรับไปพิจารณา" + ปุ่ม "ดูงานของฉัน" (เปิดแผงร่าง `activePanel='drafts'` ที่มีแล้ว) + "แก้ต่อ".
- แถบ D-A พลิกเป็นขั้น "รออนุมัติ" ทันที (state จาก `openDraft.status='pending'`).

## 7. WCAG 2.2 AA / มาตรฐาน (Material · HIG)
- **สถานะเป็นข้อความจริง ไม่พึ่งสี** (1.4.1): status chip + stepper มีทั้งไอคอน+คำ (ร่าง/รอตรวจ/ถูกส่งกลับ/เผยแพร่แล้ว).
- **aria-live polite** สำหรับการเปลี่ยนสถานะ + `aria-current="step"` บน stepper (มี precedent `:3135,3249`).
- **ปุ่มจบงาน**: ป้ายบอกผลจริง (WCAG 3.2.4 ป้ายสม่ำเสมอ · 2.4.6 ป้ายสื่อความ) — โค้ดมีวินัยนี้แล้ว (`saveLabel`/`saveName` `:2208`). anon = "ส่งให้ทีม" (ไม่ใช่ publish disabled ที่สื่อผิด).
- **Target size AA ≥ 24px** (มี memo ทีม: match sibling `.ed-mini`=30px) — ปุ่ม stepper/finish ทำตาม.
- **ห้าม gate ด้วย `@media(hover)`** (memory `feedback_verify_hover_on_real_browser`): แถบสถานะ+ปุ่มจบงานต้องแสดงด้วย `display`/state จริง ไม่ใช่ hover.
- **HIG Feedback / M3 Snackbar**: สถานะที่ "คงอยู่" (รอตรวจ/ถูกส่งกลับ) = inline persistent, ไม่ใช่ snackbar (โค้ดมีคอมเมนต์หลักการนี้ `:3133`). snackbar/`:message` เหลือไว้เฉพาะ error ชั่วคราว.
- **ยืนยันก่อน action ที่ย้อนยาก** (HIG Alerts): เผยแพร่ทับร่างที่รอตรวจ = confirm ที่พูดผลจริง (มีแล้ว `:2181`).
