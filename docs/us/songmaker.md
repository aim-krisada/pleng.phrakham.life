# User Story + User Journey — "คนทำเพลง" (Song Maker)

> ## ⭐ North Star (P'Aim 2026-07-25 · หลักนำทุก story — เหนือ AC ทุกข้อ)
> เครื่องมือทำเพลงต้อง **สองด้านพร้อมกัน ไม่แลกกัน**:
> 1. **ง่ายสำหรับคนไม่รู้ดนตรี** — zero-training ใช้เป็นเองใน 5 นาที (ความซับซ้อนดนตรีซ่อนไว้ · progressive disclosure) · **และในเวลาเดียวกัน คนรู้ดนตรีใช้ความสามารถขั้นสูงได้เต็ม** (สัญลักษณ์/โครงสร้าง/สิทธิ์ครบ ไม่ถูกตัดทิ้งเพื่อความง่าย)
> 2. **ตรงมาตรฐานสากล 2 แกนพร้อมกัน** — (ก) **ทางดนตรี** (jianpu/notation ถูกต้องตามมาตรฐาน) + (ข) **การใช้งานซอฟต์แวร์ระดับโลก** (Material / Apple HIG / WCAG 2.2 AA · outside-in · ไม่ปะผุ)
>
> ทุก AC วัดย้อนกับ North Star นี้: *"คนไม่รู้ดนตรีทำได้ไหม · คนรู้ดนตรีทำขั้นสูงได้ไหม · ถูกทั้งมาตรฐานดนตรี+ซอฟต์แวร์ไหม"*.

> **ขอบเขตก้าวนี้ (P'Aim 2026-07-25):** เอกสารนี้ทำ **แค่ user story + user journey ของคนทำเพลงเท่านั้น** ให้ครบถ้วนสมบูรณ์ — **ยังไม่ทำ** function grouping / layout / top-bottom bar / mockup. เหตุผล: ตัวแก้เพลง v2 ตอนนี้ = "ปะผุ" (ยกเครื่องทีละจุดโดยไม่มีภาพรวม). ก่อนจัดของลงจอ ต้องรู้ก่อนว่า **คนทำเพลงเดินงานยังไง ต้องการอะไร เจ็บตรงไหน**.
>
> **เขียนที่ระดับ "need/intent" ไม่ใช่ "solution":** story/AC บอก *ผู้ใช้ต้องการอะไร ทำไม* — **ไม่ระบุ component/ปุ่ม/layout** (นั่นคือก้าวถัดไป). ชื่อของเดิมที่ reuse ได้ = ยกไปไว้ **§7 build-reference** (ใช้ตอน build ไม่ใช่ตอนนี้).
>
> **นิยาม "ครบ":** สืบจากแหล่งจริงให้ exhaustive ไม่เดา persona. แหล่ง:
> 1. **ผู้ใช้จริง = พี่เปา** — `docs/pm/bug-intake.md` BI-001..010 (ใช้ inline editor v2 จริง 24 ก.ค. · "แก้เพลงใช้ยากกว่า v1")
> 2. **โมเดล/มาตรฐาน** — `work/ปรับ pl edit ui/บทวิเคราะห์-สถาปัตยกรรม.md` + `docs/song-model-v2.md` (v2 = stanzas + arrangement · repeat/volta ทำแล้ว · D.C./D.S./Coda/Fine ยังไม่มี)
> 3. **G task-analysis** — `Downloads/วิเคราะห์-Web-App-สร้างโน้ตเพลง.md` (lifecycle · cognitive load · outside-in)
> 4. **แอปจริง** — inline editor (ดินสอ ✏️ = `SongViewer.vue`) + grid editor เก่า (`EditorMode.vue`)
> 5. **G adversarial review** ของ draft นี้ (transcript `C:\gl\.aibridge\transcripts\songmaker-journey-2026-07-25-G-*.md`) — เติม modulation, pickup bar, performance directives, Segno anchor, range voltas, cross-device/offline/IME edge cases, de-UI ตาม INVEST (Claude ตัดสินรับ/ปรับเอง — ดู §6)

## 0. ทำไมเริ่มจาก "คนทำเพลง" (ไม่ใช่คนร้อง)

แอปมี 3 บทบาท (คนร้อง S / คนทำเพลง M / ผู้ตรวจอนุมัติ R). **คนร้องใช้ง่ายอยู่แล้ว.** จุดที่พังคือฝั่งคนทำเพลง — พี่เปา (คนทำเพลงจริงคนเดียวของคลัง = คอขวด) บอกตรง ๆ ว่า v2 "แก้เพลงใช้ยากกว่า v1". ถ้าคนทำเพลงไม่ลื่น เพลงไม่เข้าคลัง คนร้องก็ไม่มีอะไรร้อง. **คนทำเพลงลื่น = ทั้งระบบเดินได้.** เอกสารนี้โฟกัสบทบาทนี้ (ผู้ตรวจ/อนุมัติ = แตะเฉพาะจุดส่งมอบ Stage 9, ไม่ลงลึก).

## 1. Persona — คนทำเพลง (M)

| ด้าน | รายละเอียด (จากของจริง) |
|---|---|
| **ใครคือ** | ตัวแทน = **พี่เปา** · คนของโบสถ์ที่รับพิมพ์/เรียบเรียงเพลงเข้าคลัง · **คอขวด** |
| **สเปกตรัมความรู้ดนตรี** | ครอบทั้ง **คนรู้ดนตรี** (อ่าน/เขียน jianpu + คอร์ด · จัดโครง/วนซ้ำ) **และคนไม่รู้ดนตรี** (ช่วยพิมพ์/นำเข้า/ตรวจ) — ตาม North Star ต้องรองรับทั้งคู่ · ไม่ควรต้องวาดสัญลักษณ์สากลเองถ้าระบบช่วยได้ |
| **ทำงานจากอะไร (3 แบบ)** | (ก) **สร้างจากศูนย์** · (ข) **พิมพ์ตามโน้ตต้นฉบับ** (กระดาษ/PDF เก่าที่โบสถ์มีเป็นร้อยเพลง = transcription ด้วยมือ) · (ค) **นำเข้า (import) จากผลของ AI/parser แล้วตรวจสอบ+แก้** — ทีมใช้ AI process หนังสือเพลงเป็นข้อมูล (`tools/parse_song.py` [[pleng-da-import-parser]]) → คนทำเพลงทำหน้าที่ **verify** ผลที่เครื่องแปลง (P'Aim 2026-07-25) |
| **ทำงานที่ไหน** | ทั้ง **มือถือ** (แก้ระหว่างวัน) และ **เดสก์ท็อป** (พิมพ์/ตรวจยาว batch) → ทุก story ผ่านทั้ง 2 (360–412px + desktop, WCAG 2.2 AA) · เน็ตโบสถ์ไม่เสถียร → ต้องทน offline |
| **งานเป็นชุด** | เพลงหลายสิบ–ร้อยเข้าคลัง · ต้องการ **เร็ว + ถูกต้อง + ทำซ้ำได้** (โดยเฉพาะ import แล้วไล่ verify ทีละเพลง) |
| **เกณฑ์สำเร็จของเขา** | "เอาเพลง 1 เพลงเข้าคลังได้เร็วและถูก (ไม่ว่าพิมพ์เองหรือ import) โดยไม่ต้องต่อสู้กับเครื่องมือ" · benchmark = **v1 (เร็วกว่า)** |

**Anti-persona:** คนร้อง/ฟัง (S) และผู้ตรวจ (R) — เครื่องมือแก้ต้องไม่ไปรกจอ 2 บทบาทนั้น. (แต่คนทำเพลงเองต้อง "ฟังตรวจ" งานตัวเอง = ยืมความสามารถฝั่ง S มาใช้ตอน verify.)

**ปวดที่สุดตอนนี้ (จาก BI):** (1) พิมพ์เนื้อไม่ต่อเนื่อง (BI-005) · (2) แทรก/ลบ/แก้ตรงจุดไม่ได้ (BI-008) · (3) เครื่องหมายลบ-ใส่ไม่ได้/ไม่ auto (BI-003/009) · (4) คัดลอก-วางไม่รู้วางตรงไหน (BI-004) · (5) ฟังเฉพาะห้องไม่ได้ (BI-006) · (6) แก้เสร็จไม่รู้จะเผยแพร่ยังไง (BI-007). **ทั้งหมด = "งานพื้นฐานที่ v1 ทำได้ แต่ v2 สะดุด".**

## 2. User Journey — ทำ/แก้เพลง 1 เพลง ตั้งแต่ต้นจนจบ

โครง lifecycle อ้าง G (Setup → Composition → Arrangement → Review & Delivery) แตกละเอียดตามงานจริง. แต่ละสเตจ = **[ทำอะไร] · [ต้องการอะไร] · [เจ็บตรงไหน — อ้าง BI/คำพี่เปา/model gap]**. ครอบ 2 ทางเข้า: (ก) สร้างใหม่ · (ข) แก้เพลงเดิม.

### Stage 0 — ตัดสินใจเริ่ม (เข้าทาง · 3 ทาง)
- **ทำ:** เลือกทางเข้า 1 ใน 3 — (ก) *สร้างใหม่จากศูนย์* · (ข) *เปิดเพลงเดิมมาแก้* (ค้นหาให้เจอ) · (ค) *นำเข้า (import) เพลงที่ AI/parser แปลงไว้ มาตรวจสอบ+แก้* · ถ้ามีงานค้าง = ทำต่อจากร่าง
- **ต้องการ:** จุดเริ่มชัดทั้ง 3 ทาง · เปิดเพลง/ผล import แล้วเข้าตรวจ-แก้จากตรงที่เห็น
- **เจ็บ:** P'Aim — "การเลือกเพลงเพื่อแก้ / สร้างเพลงใหม่ ... ดูใช้ยาก" · (ทาง import + verify = sub-journey แยก ดู Stage 10)

### Stage 1 — ตั้งค่าเพลง (Setup) *(เพลงใหม่)*
- **ทำ:** ตั้งชื่อ · คีย์ · อัตราจังหวะ · ความเร็ว · เลขที่/เล่ม
- **ต้องการ:** กรอกเร็ว ค่าเริ่มต้นสมเหตุผล แก้ทีหลังได้
- **เจ็บ:** จมอยู่ในกองปุ่มที่รก (G: cognitive load สูง)

### Stage 2 — ใส่ทำนอง: โน้ตตัวเลข (melody)
- **ทำ:** พิมพ์ 1–7 · จุด octave บน/ล่าง · ความยาว/ลาก (`-`) · เชื่อม (`~`/tie) · แบ่งห้อง (`|`) · **ห้องยก (pickup/anacrusis)** ที่ต้นเพลง
- **ต้องการ:** พิมพ์ลื่นเหมือนพิมพ์ข้อความ · แก้ตัวที่ผิดตรงจุด · แป้นพิมพ์เพี้ยน (ไทย/อังกฤษ) ไม่ทำพัง
- **เจ็บ:** **BI-008** แทรก/ลบเด้งมั่ว แก้ตรงจุดไม่ได้ · **BI-009** octave `'` ซ้ำปุ่มสูง/ต่ำ + ต้องจัดตำแหน่งเอง · **BI-005** ตัวอักษรอังกฤษหลุด (IME/แป้นเพี้ยน)

### Stage 3 — ใส่เนื้อร้อง (lyrics)
- **ทำ:** พิมพ์เนื้อไทยใต้โน้ต **1 พยางค์ = 1 โน้ตที่ตี** · แยกคำ · เอื้อน · หลายข้อบนทำนองเดียว
- **ต้องการ:** พิมพ์รวดเดียวทั้งท่อน ระบบแบ่งพยางค์ให้ · หรือพิมพ์แล้วเด้งโน้ตถัดไปเอง
- **เจ็บ:** **BI-005 (flagship "v1 ดีกว่าเยอะ")** — ต้องพิมพ์ทีละคำ · P'Aim อยากได้ space = แบ่งพยางค์ + ripple

### Stage 4 — ใส่คอร์ด + คีย์
- **ทำ:** ใส่คอร์ด (G, Em, Am, C) เหนือโน้ต/ห้อง · 2 คอร์ด/ห้อง · **เปลี่ยนคีย์กลางเพลง** (ท่อนส่งขึ้นคีย์)
- **ต้องการ:** คอร์ดตรงตำแหน่ง · transpose แล้วคอร์ด+โน้ตตามคีย์ · เปลี่ยนคีย์เฉพาะช่วงได้
- **เจ็บ:** 2 คอร์ด/ห้องยังไม่ครบ (issue21 ⚠️) · **modulation ยังไม่มีในโมเดล** (มีแค่ global key)

### Stage 5 — จัดโครงสร้าง + การวนร้อง (Arrangement) ⭐ *ซับซ้อนสุด*
- **ทำ:** แบ่ง/ตั้งชื่อท่อน (ข้อ1/รับ/ท่อนส่ง) · จัดลำดับการร้อง · ใส่:
  - **‖: :‖** ซ้ำท่อน · **กล่อง 1./2./…/N** (volta หลายรอบ · เช่น 1.-3. vs 4.)
  - **D.C. / D.S. + จุดปัก Segno 𝄋 / To Coda + Coda 𝄌 / Fine / เส้นจบเพลง** (double barline)
  - **ร้องรับรายข้อ** (รับโชว์ครั้งเดียว ร้องหลายรอบ)
  - **ย้อนกลางห้อง** (จุดซ้ำไม่ตรงเส้นห้อง)
  - **คำสั่งการร้อง** (เดี่ยว/พร้อมกัน/ดนตรีรับ/[ดนตรีส่ง]/สร้อย) = ป้ายข้อความ ไม่ผูกทำนอง
- **ต้องการ:** จัดลำดับด้วยการลากบล็อกโดยไม่ต้องวาดสัญลักษณ์เอง · ระบบสร้างสัญลักษณ์วนซ้ำให้ · แต่คนรู้ดนตรีใส่ตรง ๆ ได้ · แก้ทำนองที่เดียว ทุกข้อที่ใช้ตาม
- **เจ็บ:** **BI-004** คัดลอก-วางไม่รู้วางตรงไหน + เลื่อนทีละบรรทัด · **model gap** D.C./D.S./Coda/Fine/Segno + ย้อนกลางห้อง + คำสั่งการร้อง ยังไม่มี (ถ้าไม่มี ผู้ใช้ยัดคำสั่งลงบรรทัดเนื้อ → พังพยางค์)

### Stage 6 — ฟัง/ตรวจด้วยหู (Review)
- **ทำ:** กดเล่นฟัง · เทียบต้นฉบับ · ฟังเฉพาะจุดที่แก้
- **ต้องการ:** เล่น **ทั้งเพลง/ท่อน/บรรทัด/ห้อง** · ไฮไลต์วิ่งตามพยางค์ · หยุดได้เสมอ
- **เจ็บ:** **BI-006** เล่นเฉพาะห้องไม่ได้ · **BI-002** เข้าแก้ระหว่างเล่น → เสียงค้าง หยุดไม่ได้
- **หมายเหตุ (parked → §8 ก้าว function-grouping):** P'Aim เสนอว่าตอนอยู่โหมดแก้ การฟัง = แค่ฟังเป็นท่อน/จุดที่สนใจ อาจ**ไม่ต้องมี play dock เต็มในหน้าแก้** — บันทึกไว้เป็นประเด็น layout ของก้าวถัดไป (ยังไม่ตัดสิน · ที่นี่ story คงแค่ need "ฟังตรวจเป็นจุดได้")

### Stage 7 — แก้/ขัดเกลา (iterate)
- **ทำ:** พบผิด → แก้โน้ต/เนื้อ/คอร์ด/สัญลักษณ์ตรงจุด · undo/redo
- **ต้องการ:** คลิกโน้ต = cursor ไปตรงนั้น · แทรก/ลบตรงจุด · ใส่/ลบเครื่องหมายสมมาตร · **แก้ทำนองที่หลายข้อใช้ร่วม โดยไม่พังข้ออื่นโดยไม่ตั้งใจ**
- **เจ็บ:** **BI-008** Delete=Backspace ไม่ต่าง แก้ทับไม่ได้ · **BI-003** ลบ/ใส่ซ้ำเครื่องหมายไม่ได้ · **BI-009** `~` ไม่เชื่อม · `()` ไม่ชัด · ขาด #/b · **shared-stanza trap** แก้ข้อ 3 แต่ข้อ 1-2 พังตาม

### Stage 8 — บันทึก/ส่งมอบ (Delivery)
- **ทำ:** เซฟงาน · (ถ้ามีสิทธิ์) ส่งตรวจ / เผยแพร่เข้าคลัง
- **ต้องการ:** รู้ชัดว่าเซฟแล้วยัง (ไม่หาย · ทน offline/เน็ตหลุด) · รู้ว่า "จบงาน" ทำยังไงตามบทบาท
- **เจ็บ:** **BI-007** ทำได้แค่ "บันทึกร่าง" ไม่รู้จะเผยแพร่ยังไง · ปุ่มกำกวม · สถานะบันทึกไม่ชัด

### Stage 9 — (ผลพลอยได้) preview / print / แชร์ขอความเห็น
- **ทำ:** preview ก่อนพิมพ์ A4 (แบบประหยัดกระดาษที่โบสถ์คุ้น) · แชร์ลิงก์ให้คนช่วยตรวจ
- **ต้องการ:** เห็นก่อนพิมพ์ · สลับ *มุมมองต่อเนื่อง (ฝึกร้อง)* กับ *ประหยัดกระดาษ (พิมพ์)*
- **เจ็บ:** **BI-010** แชร์/QR ลิงก์ `127.0.0.1` เปิดมือถือไม่ได้

### Stage 10 — sub-journey: นำเข้า + ตรวจสอบ (Import & Verify) ⭐ *ทางเข้าที่ (ค) · P'Aim 2026-07-25*
บริบท: ทีมใช้ AI/parser (`tools/parse_song.py`) แปลงหนังสือเพลง (DOCX/PDF/สแกน) → v2 JSON เป็นชุด. **ผลของเครื่อง = ยังไม่เชื่อถือ 100%** → งานของคนทำเพลงเปลี่ยนจาก "พิมพ์" เป็น **"ตรวจสอบ+แก้ให้ถูก"**. sub-journey นี้แทรกก่อนเข้า Stage 6–8 (ฟัง/แก้/ส่งมอบ ใช้ร่วมกัน).

- **10a นำเข้า:** รับผล import (ทีละเพลง/ชุด) · เห็นคิวรอ verify · **รู้ที่มา (provenance)** ว่าเพลงนี้ import จากไฟล์ต้นฉบับไหน · **ถ้า AI พังทั้งเพลง = reject/ทิ้งจากคิวได้เลย** (ไม่ต้องไล่แก้) · **ถ้าซ้ำเพลงในคลัง = เลือกสร้างใหม่/อัปเดตทับ/ยกเลิก**
- **10b ตรวจเทียบต้นฉบับ:** ดูผล AI เทียบต้นฉบับ (เปิดไฟล์ต้นฉบับควบคู่ได้) · เห็น **จุดที่ AI น่าจะพลาด** เด่น + **กระโดดไปจุดเสี่ยง/confidence ต่ำ** ได้ (ไม่ต้องไล่อ่านทั้งเพลง)
  - *เจ็บ (คาด):* ถ้าไม่ชี้จุดเสี่ยง คนต้องไล่เทียบมือทั้งเพลง = ช้าเท่าพิมพ์เอง (เสียประโยชน์ import)
- **10c แก้ + ฟังตรวจ:** แก้จุดผิด (เครื่องมือเดียวกับ Stage 7) · **ฟังเสียง synth ของผลที่แปลง** เพื่อจับโน้ตเพี้ยนด้วยหู (ยืม Stage 6)
- **10d ยืนยัน/ส่ง (bulk):** ทำเครื่องหมาย "ตรวจแล้ว" รายเพลง → ส่งเข้า flow ส่งมอบ (Stage 8) · ไล่หลายเพลงต่อเนื่อง **ข้ามเพลงยากไปทำง่ายก่อนแล้ววนกลับ** ได้ · **คิวไม่รวนถ้าปิด/เน็ตหลุดกลางคัน** (จำสถานะ) · **กันกด mass-approve ทั้งชุดที่ยังมีเพลงเสี่ยง**

**เส้นทางจริงวนไป-กลับ:** คนทำเพลงวน "พิมพ์/นำเข้า (2–5, 10) ↔ ฟังตรวจ (6) ↔ แก้ (7)" หลายรอบก่อนถึง 8. เครื่องมือต้องรองรับการวนนี้ ไม่ใช่ทางตรงครั้งเดียว.

## 3. User Stories + Acceptance Criteria

รูปแบบ *As คนทำเพลง (M), I want …, so that …* + AC ทดสอบได้. AC โยงแหล่งจริง. ธง: 🆕 = ความสามารถ/โมเดลใหม่ · ♻️ = ต่อยอดของเดิม · ⚠️ = ต้องยืนยันสถานะจริงตอน build.

> **North star ร่วม** (ไม่เขียนซ้ำทุก story): (a) ลื่น/เร็ว ≥ v1 · (b) มือถือ 360–412px + เดสก์ท็อป ไม่มี h-scroll · (c) WCAG 2.2 AA · (d) แก้ทำนองที่เดียว ทุกข้อที่ใช้ตาม · (e) ไม่ทำงานหาย (autosave/undo/ทน offline).
> **AC เขียนที่ระดับ need** — ไม่ระบุ component. ของเดิมที่ reuse ได้ → §7.

### EPIC M1 — เข้าเริ่มงาน

**US-M1.1 — สร้างเพลงใหม่.** *…I want เริ่มเพลงใหม่จากจุดที่หาเจอง่าย, so that ลงมือพิมพ์ได้ทันที.*
- AC1 จุดเริ่ม "สร้างเพลงใหม่" ที่คนทำเพลงหาเจอโดยไม่ต้องสอน
- AC2 เริ่มแล้วได้แผ่นเปล่าพร้อมพิมพ์ทันที (ไม่บังคับกรอก setup ครบก่อน)
- AC3 ทำได้ทั้งเดสก์ท็อป + มือถือ

**US-M1.2 — เปิดเพลงเดิมมาแก้.** *…I want เปิดเพลงที่มีอยู่แล้วเข้าแก้จากตรงที่เห็น, so that ไม่หลุดบริบท.*
- AC1 ค้น/หาเพลงเจอเร็ว
- AC2 เปิดเพลง → เห็นแผ่น (อ่านได้) → เข้าแก้ **บนแผ่นเดิม** ไม่โหลดหน้าใหม่ ♻️
- AC3 กดออกจากแก้ → กลับเป็นแผ่นอ่านเหมือนเดิม

**US-M1.3 — ทำงานต่อจากร่างเดิม + กันชนข้ามเครื่อง.** *…I want กลับมาทำงานที่ค้างต่อได้ และรู้ถ้ามีฉบับใหม่กว่าบนอีกเครื่อง, so that งานไม่หายและไม่ทับกันเอง.*
- AC1 งานที่ยังไม่จบเก็บเป็น working copy อัตโนมัติ · เปิดกลับมาเห็นตรงที่ค้าง 🆕
- AC2 เห็นรายการ "งานของฉัน" (ร่าง/รอตรวจ/ส่งกลับ/อนุมัติ) เข้าถึงตรง ⚠️ (BI-007 ผูก)
- AC3 **ถ้ามีฉบับที่ใหม่กว่าบนอีกเครื่อง/แท็บอื่น → เตือนก่อนทับ + ให้เลือกฉบับ** (ไม่เงียบ ๆ ทับของใหม่) 🆕 (G edge 3.1)

**US-M1.4 — ตั้งค่าเพลง.** *…I want ตั้งและแก้ค่าหลักของเพลงเมื่อไหร่ก็ได้, so that ไม่ต้องรู้ครบตั้งแต่แรก.*
- AC1 ตั้ง ชื่อ · คีย์ · อัตราจังหวะ · ความเร็ว · เลขที่/เล่ม ♻️
- AC2 แก้ได้ทุกเมื่อ (ไม่ล็อก)

**US-M1.5 — ลบเพลง/ยกเลิกงาน.** *…I want ลบเพลงหรือทิ้งงานที่ทำผิด, so that คลังไม่รก และไม่ลบพลาด.*
- AC1 ลบเพลง/ทิ้งร่างได้ · **ยืนยันก่อนลบ + กู้คืนได้ระยะหนึ่ง** (กันลบพลาด) 🆕 ⚠️ (เดิม issues10 "ลบทั้งเพลง")

### EPIC M2 — ใส่ทำนอง (โน้ตตัวเลข)

**US-M2.1 — พิมพ์โน้ตลื่น + แป้นพิมพ์ไม่พัง.** *…I want พิมพ์ 1–7 แล้วโน้ตขึ้นและเดินตัวถัดไปเอง โดยแป้นพิมพ์ไทย/อังกฤษไม่ทำเพี้ยน, so that พิมพ์ทำนองยาวรวดเดียวได้.*
- AC1 พิมพ์ 1–7 = ใส่/เปลี่ยนโน้ต เห็นผลบนแผ่นสด ♻️
- AC2 พิมพ์ต่อเนื่องเดินช่องถัดไปเอง (ไม่ต้องคลิกทีละช่อง) 🆕 (BI-005)
- AC3 **รับ input ถูกไม่ว่าสถานะแป้นพิมพ์ OS จะไทย/อังกฤษ** — เลข/สัญลักษณ์ไม่กลายเป็นตัวอักษรไทย, ไม่มีตัวแปลกหลุด 🆕 (BI-005 + G edge 3.3)

**US-M2.2 — ใส่ octave สูง/ต่ำ ไม่สับสนวิธี.** *…I want ใส่ octave บน/ล่างโน้ตด้วยการกดหรือแตะแบบใดก็ได้อย่างไม่สับสน แล้วมันไปอยู่ถูกที่เอง, so that ไม่ต้องจัดตำแหน่งเองและไม่งงว่ามีหลายวิธีที่ทำเรื่องเดียวกัน.*
- AC1 ใส่ octave แล้ว **auto-position ถูก** (บน/ล่างตัวเลข) ไม่ต้องจัดเอง 🆕 (BI-009 ข้อ 2)
- AC2 วิธีป้อน octave ไม่ทำให้ผู้ใช้สับสนว่าซ้ำซ้อน (ปัจจุบันมีทั้งปุ่มสูง/ต่ำ และ `'` = งง) — **ผลลัพธ์เดียว ไม่ว่าจะป้อนทางไหน** 🆕 (BI-009 ข้อ 1) *(วิธีจัด UI = ก้าวถัดไป)*

**US-M2.3 — ความยาว/ลาก/เชื่อมโน้ต.** *…I want ใส่โน้ตค้าง (`-`) และเชื่อมเสียง (tie) ได้จริง, so that ทำนองลากยาว/เอื้อนถูกตามที่ร้อง.*
- AC1 `-` = ลากเสียงต่อ ♻️
- AC2 `~`/tie = **เชื่อมโน้ตจริง** (ปัจจุบันกดแล้วไม่เชื่อม) 🆕 (BI-009 ข้อ 3 bug)
- AC3 แบ่งห้อง `|` ได้

**US-M2.4 — เครื่องมือสัญลักษณ์ครบตามมาตรฐาน jianpu.** *…I want เครื่องมือใส่สัญลักษณ์โน้ตครบตามมาตรฐาน jianpu, so that ทำเพลงที่มีสัญลักษณ์ครบทุกแบบได้ ไม่ติดว่า "ระบบไม่มีตัวนี้".* (P'Aim 2026-07-25 — "ต้องมีเครื่องมือครบตามมาตรฐาน")
- AC1 ครอบชุดสัญลักษณ์มาตรฐาน jianpu อย่างน้อย: **โน้ต 1–7 + พัก `0`** · **octave** (จุดบน/ล่าง หลายชั้น) · **ความยาว** (ขีดใต้ = แบ่งครึ่ง/eighth/sixteenth · `-` ลากเสียง · จุดประ dotted) · **tie/slur** (โยงเสียง/เอื้อน) · **accidental `#`/`b`/`n`** · **เส้นห้อง `|` + เส้นจบ + `‖: :‖`** · **grace note / fermata (⌒)** · **caesura / หยุดสนิท `//`** 🆕 · **breath / phrase mark หายใจ `'`** 🆕 · **measure-repeat `%` (ซ้ำห้องก่อนหน้า · simile · ประหยัดพื้นที่ vamp)** 🆕 — enumerate ครบเป็น checklist ที่ทดสอบได้ ⚠️ (verify แต่ละตัวว่ามี/ยัง — หลายตัวมีแล้ว: [[fermata-build]] · double-dot · beam-levels)
- AC2 ตัวไหน "มาตรฐานมีแต่ระบบยังไม่มี" = ธง 🆕 ให้ DS/dev เติม (ห้ามเงียบว่าครบทั้งที่ขาด)
- AC3 (คู่ North Star) สัญลักษณ์ขั้นสูงมีให้คนรู้ดนตรี **แต่ไม่รกจอคนไม่รู้ดนตรี** (progressive disclosure)
- *(N-review 2026-07-25 fold: caesura / breath / measure-repeat = สัญลักษณ์มาตรฐานที่คลังยังไม่มี — MusicXML `<caesura>` (grand pause) · `<breath-mark>` + SMuFL `breathMarkComma` U+E4CE (จุดหายใจช่วยร้องพร้อมกัน เนื้อไทยประโยคยาว) · `<measure-repeat>` + SMuFL `repeat1Bar` U+E500 (vamp กีตาร์ซ้ำห้อง). ทั้งสามจัดเป็นขั้นสูง A ตาม AC3 · caesura ≠ fermata (ตัดเสียง vs ค้างเสียง))*

### EPIC M3 — ใส่เนื้อร้อง

**US-M3.1 — พิมพ์เนื้อต่อเนื่อง 1 พยางค์/โน้ต.** *…I want พิมพ์เนื้อแล้วเด้งไปพยางค์/โน้ตถัดไปเอง, so that ใส่เนื้อทั้งท่อนลื่น ไม่ต้องพิมพ์ทีละคำ (≥ v1).*
- AC1 พิมพ์พยางค์ → เดินพยางค์ถัดไป (คำใหม่) 🆕 (BI-005)
- AC2 แยกคำข้ามโน้ต · เอื้อน (พยางค์เดียวหลายโน้ต) ทำได้ ♻️
- AC3 พิมพ์รวดเดียวหลายพยางค์ไม่สะดุด — verify ด้วยการพิมพ์จริง ไม่ใช่แค่ querySelector

**US-M3.2 — วางเนื้อยาวแล้วระบบแบ่งพยางค์ให้.** *…I want วางประโยคยาวแล้วให้เว้นวรรคกลายเป็นตัวแบ่งพยางค์ลงโน้ตอัตโนมัติ, so that ไม่ต้องเคาะทีละพยางค์.*
- AC1 วาง/พิมพ์เนื้อยาว → เว้นวรรค = แบ่งพยางค์ → apply ลงโน้ต 🆕 ♻️ (มี bulk lyric เดิม)
- AC2 ตรวจ/แก้การแบ่งพยางค์ก่อน apply ได้ (กันแบ่งผิด)
- AC3 *(ทางที่ดีสุด = เสนอตอน DS — P'Aim ขอให้ช่วยดู ดู §5 ข้อ 1)*

**US-M3.3 — หลายข้อบนทำนองเดียว + กันแก้กระทบข้ออื่น.** *…I want ทำหลายข้อบนทำนองเดียวโดยพิมพ์แค่เนื้อที่ต่าง และไม่แก้ข้ออื่นพังโดยไม่ตั้งใจ, so that reuse ทำนองได้อย่างปลอดภัย.*
- AC1 เพิ่มข้อใหม่ = เนื้อใหม่บนทำนองเดิม (share) ♻️ (v2 arrangement)
- AC2 **ก่อนแก้ทำนองที่หลายข้อใช้ร่วม → เตือนให้เห็นว่า "กระทบข้อ 1,2,3" + ให้เลือก "แก้ร่วม" หรือ "แยกข้อนี้ออก (make unique)"** 🆕 (G edge 3.2 — shared-stanza trap)
- AC3 แก้ทำนองร่วมแล้ว undo คืนได้ทันที (กู้เมื่อพลาด)

### EPIC M4 — คอร์ด + คีย์

**US-M4.1 — ใส่คอร์ด.** *…I want ใส่คอร์ดตรงตำแหน่งรวม 2 คอร์ด/ห้อง, so that คอร์ดตรงทำนองจริง.*
- AC1 ใส่คอร์ดเหนือโน้ต/ต้นห้อง ♻️
- AC2 2 คอร์ด/ห้อง ได้ ⚠️ (issue21)
- AC3 บนมือถือใส่คอร์ดได้ (คีย์บอร์ดไม่มีปุ่มพิเศษ → มีทางป้อน) 🆕

**US-M4.2 — เปลี่ยนคีย์ทั้งเพลง (transpose).** *…I want เปลี่ยนคีย์ทั้งเพลง, so that ให้เข้ากับเสียงร้อง/เครื่องดนตรี.*
- AC1 เปลี่ยนคีย์ → คอร์ด + โน้ต transpose ตาม ♻️

**US-M4.3 — เปลี่ยนคีย์กลางเพลง (modulation).** *…I want เปลี่ยนคีย์เฉพาะช่วง (เช่นท่อนส่งขึ้นคีย์), so that เพลงที่ modulate แสดง/เล่นถูก.*
- AC1 กำหนดจุดเปลี่ยนคีย์กลางเพลง → ตั้งแต่จุดนั้น pitch ของเลข jianpu + คอร์ด อิงคีย์ใหม่ 🆕 **(โมเดลยังมีแค่ global key — ต้องเติม)** (G missing 1.1)
- AC2 แสดงป้ายเปลี่ยนคีย์บนแผ่น + เล่นเสียงถูกตามคีย์ใหม่ 🆕
- AC3 *(⚠️ ยืนยันมีเพลงจริงในคลังที่ต้องใช้ก่อนจัดลำดับ — §5)*

### EPIC M5 — แก้ตรงจุด ⭐ *หัวใจ "v1 ดีกว่า"*

**US-M5.1 — คลิกโน้ต/คำ = cursor ไปตรงนั้น.** *…I want แตะโน้ต/คำบนแผ่นแล้ว cursor ไปตรงนั้นทันที, so that แก้จุดที่เห็นได้เลย.*
- AC1 คลิก/แตะ → cursor + ไฮไลต์ไปตัวนั้น 🆕
- AC2 การชี้กลับต้นทางนิ่ง — แก้แล้วไม่กระทบข้ออื่นผิด (index source↔resolved ถูก) ⚠️ (risk ที่โมเดลหมายเหตุไว้เอง)

**US-M5.2 — แทรก/ลบ ตรง caret ตามคาด.** *…I want แทรกและลบตรง caret โดย Delete กับ Backspace ต่างกันชัด, so that แก้พลาดได้โดยไม่ลบยกช่อง.*
- AC1 แทรกที่ caret จริง (ไม่เด้งไปที่อื่น) 🆕 (BI-008)
- AC2 Delete ≠ Backspace ตาม help ที่แสดง 🆕 (BI-008)
- AC3 ลบทำงานจริงทั้ง 2 แบบ (ดึงชิด / เหลือช่องว่าง) — verify ด้วยการกดจริง

**US-M5.3 — พิมพ์ทับแก้ตรงจุด.** *…I want พิมพ์ผิดแล้วแก้ทับตรงนั้นต่อได้, so that ไม่ต้องลบทั้งช่องเพื่อแก้ตัวเดียว.*
- AC1 เลือกโน้ต + พิมพ์ = ทับตัวนั้น ♻️
- AC2 มีทั้งพฤติกรรม "ทับ" (บรรทัดไม่ขยับ) และ "แทรก/ripple" 🆕 (BI-008)

**US-M5.4 — ใส่/ลบเครื่องหมายสมมาตรทุกตัว.** *…I want ใส่ ลบ และกดซ้ำเครื่องหมายได้ครบทุกตัว, so that แก้เครื่องหมายได้เหมือนแก้ตัวหนังสือ.*
- AC1 apply/remove เครื่องหมาย **toggle สมมาตรครบทุกตัว** 🆕 (BI-003)
- AC2 นิยาม `( )` และอื่น ๆ ให้ชัด + จัดกลุ่ม accidental `n`/`#`/`b` เป็นชุดเดียว ตามมาตรฐาน jianpu 🆕 (BI-009 ข้อ 4,5)

**US-M5.5 — ย้อน/ทำซ้ำ (undo/redo) ทุกการแก้.** *…I want undo/redo ได้ทุกการกระทำ, so that กล้าลองและกู้เมื่อพลาด.*
- AC1 undo/redo ครอบคลุมโน้ต/เนื้อ/คอร์ด/สัญลักษณ์/โครงสร้าง ⚠️ (ยืนยัน coverage)

### EPIC M6 — จัดโครงสร้าง + การวนร้อง ⭐ *ผูกโมเดล*
