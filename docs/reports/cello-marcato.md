# 5.1 🔴 "กระตุกเป็นช่วง ๆ" = **บั๊กจริง · PM ถูก · แต่คนละสาเหตุกับที่ PM เดา**

**สรุป: หูของ P'Aim ถูก · PM ถูกที่ว่าเป็นบั๊กไม่ใช่ "effect เกินไป" · แต่ต้นเหตุไม่ใช่ความดัง — คือ "หัวเสียง"**

## ที่ PM เดา — วัดแล้ว **ไม่ใช่**

PM เดาว่า `_p_g` ยาวกว่า + ไลบรารีเหวี่ยง 14.7 dB → ความดังไม่เท่า → กระตุก
**วัดทีละ pitch แล้ว: ความดังแทบไม่ต่าง** — median |Δ| = **1.43 dB** · สูงสุด 2.91 dB · **0 จาก 17 pitch ที่ต่างเกิน 3 dB**
(เพราะเครื่องมืออบ makeup แยกให้แต่ละชุดอยู่แล้ว: `_d` +13.07 · `_g` +12.94 = ต่างกันแค่ 0.13 dB)
จูนก็ไม่ใช่ — median 2.1¢ (ตัวที่เพี้ยน 23¢ คือโน้ต 84 ซึ่งทำนองไม่เคยแตะ)

## ต้นเหตุจริง — **หัวเสียงคนละแบบสิ้นเชิง**

| |ต่างกันทีละ pitch (median)|
|---|---|
| ความดัง | 1.43 dB ✅ ไม่ใช่ปัญหา |
| จูน | 2.1 ¢ ✅ ไม่ใช่ปัญหา |
| **หัวเสียงไต่ (t50)** | **200 ms** 🔴 **สูงสุด 580 ms** |

**ดูรูปคลื่นจริง (โน้ต C3 · ช่องละ 50ms · % ของจุดดังสุด):**
```
_d (คันชักลง) : 22 26 33 41 51 55 63 69 75 75 74 71 ...   ← ค่อย ๆ บวมขึ้น ~400ms
_g (คันชักขึ้น): 81 100 75 69 66 62 84 98 90 89 84 90 ...  ← เริ่มที่ 81% พุ่ง 100% ใน 100ms
```
**= คนละท่าเล่นกันคนละเรื่อง** ไม่ใช่ take เดียวกัน 2 ครั้ง · `_d` = สีเบาค่อย ๆ บวม · `_g` = มาเต็มตั้งแต่แรก

→ **สลับโน้ตเว้นโน้ต = โน้ตนึงค่อย ๆ ฟูขึ้น โน้ตถัดมาโผล่มาเต็มทันที สลับกันไปเรื่อย ๆ**
→ **"กระตุก" และ "เป็นช่วง ๆ" (เป็นคาบ) เป๊ะตามที่ P'Aim ได้ยิน** · **P'Aim ได้ยินของจริง ไม่ใช่รู้สึกไปเอง**

## ❌ normalize ไม่ได้ — และ**ไม่ควรทำ**

PM สั่งว่า "ต่างจริง = normalize ให้เท่า" — **ความดัง normalize ได้ แต่หัวเสียง normalize ไม่ได้ครับ**
- จะให้ `_g` บวมช้าเท่า `_d` = ต้อง**ยัด fade-in ปลอม 400ms** → **นั่นคือ "swell สังเคราะห์" ตัวเดียวกับที่ทำ Iowa เป็น "หวูดเรือ"** แล้วโดน P'Aim ตัดทิ้ง
- จะให้ `_d` มาเต็มเท่า `_g` = **ตัดการบวมทิ้ง** → **ทิ้งสิ่งที่ทำให้ `p` นุ่มและ P'Aim ชอบ**

**→ 2 take นี้ใช้สลับกันไม่ได้โดยธรรมชาติ · และการทำให้มันเหมือนกันจะทำลายเหตุผลที่เราเลือก `p` ตั้งแต่แรก**

## ✅ เสนอ: **พัก RR ตามที่ P'Aim เสนอเอง — และประหยัด 1.09 MB**

P'Aim พูดเองว่า *"ถ้ายุ่งก็พักได้"* → **ตัวเลขบอกว่าไม่ใช่แค่ยุ่ง แต่มันขัดกันโดยโครงสร้าง**
**ปิดปุ่มไว้เป็นค่าเริ่มต้นอยู่แล้ว** (ไม่ต้องแก้อะไร) · **ไม่ต้องจ่าย 1.09 MB** · ปุ่มยังอยู่ให้ลองได้ถ้าอยาก
_(หมายเหตุ: คนอัดใส่ `seq_length=2` สลับ `_d`/`_g` ก็จริง — แต่ของเขาใช้ในบริบทที่ทุกโน้ตมีหัวโน้ตชัดอยู่แล้ว ไม่ใช่เอามาลากยาวเป็นตัวโน้ตแบบเรา)_

## 4.2 ✅ Vibrato เชลโล — **ทำแล้ว ใช้ค่าของคนอัดเป๊ะ**

🎧 หมุนปุ่ม **"สั่นนิ้ว (vibrato)"** ที่ <http://10.189.195.98:5460/docs/spikes/cello-marcato.html>
**เริ่มที่ปิด** (ตามที่คนอัดตั้งมา) · ลากได้ถึง 22 cents

**เอาค่าเขามาทั้งชุด พร้อมเหตุผลที่เขาเขียนกำกับ:**

| ค่า | ที่มา | เหตุผลของเขา |
|---|---|---|
| **4.02 Hz** | `lfo01_freq=2` + `freq_oncc112=8` × `set_cc112=32` | "ช้ากว่า 2 Hz ฟังแย่มาก · เร็วประมาณนี้คือสุดที่เชลโลทำได้" |
| **0–22 cents** | `lfo01_pitch_oncc111=22` · ไม่มี `set_cc111` = **0** | **"พร้อมแล้ว อยากได้ก็หมุน"** → ผมตั้งเริ่มที่ 0 ตามเขา |
| **หน่วง 177 ms** | `delay_oncc115=0.5` × `set_cc115=45` | โน้ตนิ่งก่อน แล้วค่อยสั่น |
| **ไล่ขึ้น 177 ms** | `fade_oncc116=0.5` × `set_cc116=45` | ไม่สั่นเต็มทันที |

**⚠️ smplr ทำ vibrato ไม่ได้ตรง ๆ** — มันเซ็ต `source.detune.value` ครั้งเดียวแล้วไม่คืน node ให้ →
แก้ด้วยการ**ดักจับ voice ตอนที่มันถูกสร้าง** แล้วต่อ LFO ของเราเองเข้า `detune` ของแต่ละ voice
(อยู่ในไฟล์ spike เท่านั้น · ไม่ได้ fork smplr · ไม่ได้แตะโค้ดที่ deploy)

**✅ พิสูจน์ว่าสั่นจริงตามค่าที่ตั้ง (ไม่ใช่แค่ "เสียงเปลี่ยน"):**
วัดพิตช์ของโน้ตยาวสุด (โน้ต 66 · 2.64 วิ) ทีละเฟรม **โดยล็อกช่วงค้นหาไว้ ±1 เสียงรอบโน้ตที่เขียน** (กันหลอกตัวเอง):
**ปิด = แกว่ง 14.5 cents** (การแกว่งธรรมชาติของไฟล้เอง + noise การวัด) → **เปิด = แกว่ง 43.5 cents**
**ทฤษฎีบอกว่าควรได้ 44** (±22) → **วัดได้ 43.5 = ตรง** ✅
_(ครั้งแรกผมวัดได้ 1902 vs 1937 cents = มั่วสิ้นดี เพราะตัวจับพิตช์กระโดดฮาร์โมนิก — **โรคเดิม** เลยล็อกช่วงค้นหาแล้ววัดใหม่)_

**ยังไม่ได้ทำ: EQ 1800 Hz ขยับตาม vibrato** (เขาบอกว่านี่คือตัวกันความสังเคราะห์) — ต้องใส่ BiquadFilter
ต่อ voice + ผูก LFO ตัวเดียวกัน = **ไม่ใช่ของง่าย** → **ข้ามตามที่ brief บอก "ไม่ง่าย = ข้าม รายงาน"**
(ถ้า P'Aim ชอบ vibrato แล้วยังรู้สึก "สังเคราะห์" อันนี้คือตัวถัดไปที่ควรทำ) · **LFO ตัวที่ 2 (phase สุ่ม) ก็ยังไม่ทำ** —
ตัวเดียวยัง deterministic 100% ไม่ต้องพึ่ง `rng.js`

## 4.1 🛑 String resonance — **หยุดตามสั่ง รอ PM เคาะ** (แต่ข่าวดีกว่าที่คิด)

**PM สั่งว่า: ถ้า smplr ไม่รองรับ = งานใหญ่ → หยุด รายงาน อย่าลุยเอง** → **smplr ไม่รองรับจริง ผมเลยหยุด**

**เช็กแล้ว:** `grep resonance/sympath` ใน smplr `.d.ts` + `.mjs` = **0** · คลังเรา 120 ไฟล์ = FF/MF/MP/PP ล้วน · **res = 0**

### 💡 แต่เจอเรื่องที่พลิกสมมติฐาน — **ไม่ต้องโหลดไฟล์ใหม่เลย 0 MB**

`Res.txt` **ไม่ได้ชี้ไปที่ไฟล์ใหม่** — มันชี้กลับไปที่ **ไฟล์ PP ที่เรามีอยู่แล้ว**:
```
<region> lokey=021 hikey=022 pitch_keycenter=033 sample=PP A0.$EXT
```
**= เอาไฟล์ PP เดิมมาเล่นที่พิตช์อื่น เบา ๆ (`group_volume=-11`) หัวเสียงช้า (`ampeg_attack=0.1`)**
→ **string resonance = เสียงสายอื่นสั่นตาม ทำจากไฟล์ที่เรา ship อยู่แล้ว** · **ราคาพื้นที่ = 0 MB**

### แล้วทำไมถึงยังไม่ควรลุยเอง — **มันไม่ใช่ปัญหาไฟล์ แต่เป็นปัญหา "เหยียบเปิดตอนไหน"**

sfz ตัวจริงเปิด resonance **เฉพาะตอนเหยียบ pedal ค้าง**:
```
<group> group=1  locc64=65   ← เฉพาะ cc64 (sus pedal) >= 65
        locc$RES=1  amplitude_oncc$RES=200   ← และปุ่ม Resonance > 0
        #include "$DIR/Res.txt"
```
**แต่ระบบเราไม่มี "สถานะ pedal" เลย** — `arrange()` มี `bass:'pedal'` เป็นแค่**สไตล์การเล่นเบส** ไม่ใช่ CC64
→ **ต้องนิยามเองว่า "เพลงนี้เหยียบเปิดตอนไหน" = การตัดสินใจเชิงดนตรี ไม่ใช่งานกลไก** → **ตรงนี้แหละที่ PM บอกว่าใหญ่กว่าที่คิด**

### สรุปให้ PM เคาะ

| | |
|---|---|
| smplr รองรับไหม | **ไม่** (verify แล้ว) — ต้องเขียน trigger เอง |
| ต้องโหลดไฟล์เพิ่มไหม | **ไม่ต้องเลย** ✅ (ใช้ PP เดิม) · **+0 MB** |
| งานจริงคืออะไร | สร้าง preset จาก map ใน `Res.txt` (59 region) + Sampler ตัวที่ 2 + **นิยาม pedal เอง** |
| ความเสี่ยง | **นิยาม pedal ผิด = เสียงขุ่น/มั่ว** · และมันไปทับ **เสียงที่ P'Aim เคาะแล้วว่า "เพราะดี"** |
| ผมประเมิน | ทำได้ · แต่**ไม่ใช่ 80:20** เพราะติดที่การตัดสินใจเชิงดนตรี ไม่ใช่โค้ด |

**→ ไม่ได้ลุยต่อ รอ PM เคาะครับ** (ถ้าเคาะว่าเอา ผมทำเป็น spike + ปุ่มเปิด/ปิด ไม่แตะ preset จริง)
_(หมายเหตุ: ที่ปรึกษาเคยบอกว่า "ยืด release = sympathetic resonance" — **ผิดจริงตามที่ PM ว่า** · ของจริงคือ region แยกที่เล่นไฟล์ PP ที่พิตช์อื่น คนละกลไกกับการยืดหางเสียง)_

# ⭐ ค่าที่ P'Aim เคาะ — ล็อกแล้ว (17 ก.ค.)

**เชลโลผ่านหู P'Aim เป็นครั้งแรก หลังพักมา 2 รอบ (ไวโอลิน + Canon spike)**

| | ค่า |
|---|---|
| **ความแรงหัวโน้ต** | **5%** |
| **เลื่อนเวลาตัวโน้ต** | **10 ms** |
| **ตัวลาก / หัวโน้ต** | **`p` / `mp`** (P'Aim: "mp กับ mf พอได้ทั้งคู่ · mp นุ่มกว่าหน่อย") |

ล็อกเป็น **default ของหน้า spike** แล้ว (`PAIM_MARCATO` ใน `src/spikes/celloBakeoff.js`) →
**ทุกการทดลองต่อจากนี้ถอยกลับมาจุดนี้ได้** · **ปุ่มยังหมุนได้ตามเดิม เปลี่ยนแค่ค่าเริ่มต้น** ·
⚠️ **ยังไม่เอาเข้าแอพ** — `soundOptions.js` เชลโลยัง `disabled:true` ไม่แตะ

### 🔬 ค่าพวกนี้พิสูจน์อะไร

1. **5% = จุดที่หูฟิวส์หัวกับตัวเป็นโน้ตเดียว** — ที่ 100% หูแยกเป็น 2 เหตุการณ์ = "สะดุด" · **หัวโน้ตเป็นแค่ "ใบ้" ไม่ใช่ "ตอก"**
2. ⭐ **สมมติฐาน PM ยืนยันแล้วด้วยมือของ P'Aim เอง: 200ms → 10ms = น้อยลง 20 เท่า**
   → **หัวโน้ตยึดจังหวะแทนตัวโน้ตได้จริง** ตัว `p` บวมช้าข้างล่างได้โดยหูไม่รู้สึกช้า
   → **ตรงกับที่ผมวัดไว้ว่าหัวมาถึงก่อนตัว 145–180 ms = มีของให้หูยึด** · **ไอเดียเดียวของ P'Aim แก้ครบ 3 เรื่อง** (ขาดมิติ · แสบ · เร่ง)

## 📊 3.2 นับโน้ตซ้ำ — **นับแล้ว ยังไม่สร้าง** (ตามสั่ง)

**นับที่ "ไฟล์ต้นทาง" ไม่ใช่ "โน้ต"** ตามที่ PM สั่ง — และ**นี่คือจุดที่ PM สงสัยถูก**

| เพลงจริง | โน้ต | โน้ตต่างกัน | **ไฟล์ต่างกัน** | **ซ้ำไฟล์เดิมติดกัน** | ในนั้น = โน้ตเดียวกัน | **ซ้ำแบบมองไม่เห็น** | ซ้ำใน 2 วิ |
|---|---|---|---|---|---|---|---|
| #1 พระเจ้าเป็นความรัก | 122 | 9 | **6** | **46 (38%)** | 24 | **22** | 57 (47%) |
| #4 พระเยซูเข้าสู่ใจข้า | 151 | 10 | **7** | **46 (31%)** | 19 | **27** | 67 (44%) |
| #7 พระเจ้าทรงสร้างเรา | 140 | 8 | **5** | **62 (45%)** | 54 | 8 | 76 (54%) |
| #9 พระเจ้ารักโลก | 42 | 6 | **5** | 8 (20%) | 4 | 4 | 16 (38%) |
| #11 ขอบพระคุณ | 114 | 8 | **6** | 23 (20%) | 5 | **18** | 33 (29%) |

**อ่านตัวเลข:**
- **~1 ใน 3 ของโน้ตทำนอง เล่นไฟล์เดียวกับโน้ตก่อนหน้าเป๊ะ ๆ** (20–45% · กลาง ~31%)
- **⭐ "ซ้ำแบบมองไม่เห็น" มีจริงและเยอะ (4–27 ครั้ง/เพลง)** = **ทำนองเดินไปคนละโน้ต แต่ระบบเล่นไฟล์เดิม**
  → **PM สงสัยถูก** · ชัดสุดที่ #11 ขอบพระคุณ: ซ้ำติดกัน 23 ครั้ง **แต่เป็นโน้ตเดียวกันแค่ 5 → อีก 18 คือซ้ำที่มองจากแผ่นโน้ตไม่เห็นเลย**
- **สาเหตุ: ทำนองเพลงนมัสการอยู่ในช่วงแคบ** → ใช้ไฟล์จริงแค่ **5–7 ไฟล์จาก 17** ที่มี
- สมมติฐาน "เพลงไทย 1 พยางค์/โน้ต → ซ้ำเยอะ" = **ตัวเลขรองรับ**

**→ ตัวเลขบอกว่า "บ่อย" · แต่ "คุ้มไหม" = PM/P'Aim เคาะ ผมไม่ตัดสิน**

### 💰 ราคาจริง — **PM ประเมินต่ำไป 3.6 เท่า**

| | |
|---|---|
| PM ประเมิน (`_g` ของ `p` 17 ไฟล์) | ~0.3 MB |
| **วัดจริง** | **1.09 MB** |

เหตุ: ไฟล์ `_p_g` (คันชักขึ้น) **ยาวกว่า** `_p_d` (0.89 MB) — ไม่ใช่ 1.17÷4 ตามที่ประเมิน
→ **รวม 4.09 → 5.18 MB · คลัง 21.20 → 25.43 MB (+20% ไม่ใช่ +15%)**

**ข้อจำกัดที่ต้องรู้ก่อนตัดสิน:** `_d`+`_g` = **2 take สลับกัน** → ลดการซ้ำติดกันจาก ~31% เหลือ **~15%** ·
**ไม่ได้หายหมด** (คนอัดใส่ staccato มา 4 take ก็เพราะ 2 ยังไม่พอ) · **หัวโน้ตไม่ต้องทำ RR** — ที่ 5% แทบไม่ได้ยิน
**PM คิดถูกข้อนี้**

**3 คลิปให้เทียบ:** `p + หัว mp` · `p + หัว mf` · `p ล้วน` (ตัวเทียบ = สิ่งที่ P'Aim ฟังรอบก่อน) + `D` เปียโนอย่างเดียว

## ✅ ดีไซน์ของ P'Aim ตรงกับคนที่อัดเชลโลตัวนี้เป๊ะ

P'Aim: *"mp mf สั้น ๆ มากๆ แล้วลากด้วย p · การแสบน่าจะเกิดตอนช่วงแรกของการเริ่มสีขึ้นหรือลง"*

readme ของ Karoryfer เขียนเอง: **"staccato attacks layered on top of sustained notes"**

## 🔬 สมมติฐาน PM ที่ต้องให้หูทดสอบ (ผมยังตอบไม่ได้)

> "หัวโน้ตคมเคาะตรงบีต → หูยึดหัวเป็นตัวบอกจังหวะ → `p` บวมช้าข้างล่างได้โดยไม่รู้สึกช้า → ไม่ต้องเลื่อน `p` เลย"

## 5.2 (ก) "เปิดสั่นแล้วเสียงดังขึ้น" — **วัดแล้ว: ไม่ได้ดังขึ้นเลย ไม่มีบั๊กให้แก้**

**ทฤษฎีทำนายก่อนวัด:** vibrato = ขยับ *พิตช์* ล้วน → พลังงานต้องไม่เปลี่ยน → **|ΔRMS| < 0.3 dB** · ถ้าเกิน ~1 dB = บั๊ก

| depth 0 → 22 (เชลโลล้วน ไม่มีเปียโน/หัวโน้ต ไม่ normalize) | วัดได้ |
|---|---|
| RMS | **−0.09 dB** |
| ย่านแสบ (>2 kHz) | **−0.05 dB** |
| peak | **−0.04 dB** |

→ **ตรงทฤษฎีเป๊ะ · ไม่ใช่บั๊ก implementation** → ตามที่ brief สั่ง: **RMS เท่าเดิมแต่ฟังว่าดัง = การสั่นทำให้เด่นขึ้น → หรี่ gain ชดเชย**

**⚠️ ตัวเลข "ไม่ต่างเลยทั้ง 3 ค่า" คือหน้าตาเดียวกับ "ปุ่มไม่ทำงาน" — เลยพิสูจน์ก่อนว่าเสียงเปลี่ยนจริง:**

- `off vs off` = **maxDiff 0 เป๊ะ** → render deterministic (MP3 == live)
- `off vs on` = **maxDiff 0.134** ทั้งที่ยอดคลื่นทั้งคลิปสูงแค่ **0.080** → คลื่นเปลี่ยนเกือบสุดขั้ว = **vibrato ทำงานเต็มที่**

**→ ปุ่ม ① "หรี่เสียงตอนสั่น"** (0 → −9 dB · เริ่มที่ 0) · **ทฤษฎี −6.00 → วัดได้ −6.00 เป๊ะ** ·
**ความโหยหวนอยู่ที่ *การสั่น* ปุ่มนี้แตะแค่ *ความดัง* → หรี่ได้โดยโหยหวนเท่าเดิม** ตามที่ brief ว่าไว้

**ทดสอบแบบแฟร์ — ทำนองเดียวกัน โน้ตเดียวกัน performance เดียวกัน เปลี่ยนแค่คนสี:**

| | เส้นดัง-ค่อย | **ขยับ *ภายใน* โน้ตยาว 2.64 วิ (ตัวที่วินาที 16.5)** |
|---|---|---|
| **เปียโนสีทำนอง** | 29.7 dB | **38.6 dB** (เคาะแล้วเสียงค่อย ๆ ตาย = มีดัง-ค่อยในตัว) |
| **เชลโลสีทำนอง** | 13.2 dB | **5.4 dB** (ค้างเต็มนิ่ง) |

**ออร์แกน = เสียงที่ค้างนิ่งไม่ขยับจนกว่าจะปล่อยนิ้ว** → **นี่คือปรากฏการณ์ *ภายในโน้ต* (2.6 วิ) ไม่ใช่ *โครงเพลง* (81 วิ) — คนละสเกลเวลากันคนละโลก**

→ **PM ผูก "ออร์แกน" กับ "เส้นแบน" เป็นเรื่องเดียวกัน — ตัวเลขบอกว่าคนละเรื่อง**

→ **หลักฐานหนุน: vibrato (= การขยับ *ภายในโน้ต*) คือสิ่งเดียวที่ทำให้ P'Aim บอกว่า "มิติชัดขึ้นจริง ๆ" มาแล้ว**

→ **ตัวที่น่าจะแก้ "ออร์แกน" จริงคือปุ่ม ③ น้ำหนักคันชักขยับ** (5.49 → **8.29 dB**) — และ **คนอัดเขียนคอมเมนต์กำกับตรงจุดนี้เอง** · ⚠️ **"หายออร์แกนไหม" ผมตัดสินไม่ได้ → หู P'Aim**

### ⚠️ **ทางที่ PM สั่งให้ทำ = ปุ่มโกหก · ผมเลี่ยงแล้ว**

brief สั่ง *"overlay บน `perf` ของ `arrange()` ตรง `perf.filter(...)` ก่อนยิง sampler"* — **ทางนั้นส่งของไม่ถึงครึ่ง** เพราะ `gainToVelocityFull` บีบ gain `[0.02, 0.5]` ลงเป็น velocity ช่วงแคบ:

| ตั้งปุ่ม **12 dB** (ทั้งเพลง) | ได้จริง | เส้นสุดท้าย |
|---|---|---|
| **ทางที่ PM สั่ง** (คูณ `gain` ของ `perf`) | **+2.74 dB** | 8.52 |
| **ทาง bus** (ไหลบนมิกซ์ที่เสร็จแล้ว) ← **ผมใช้ตัวนี้** | **+6.69 dB** | **12.47** |

**→ ปุ่ม ⑤ "ความกว้างดัง-ค่อย"** (0 → 15 dB · เริ่มที่ **0 = ปิด** ไม่ใช่ 1.41 เพราะ 1.41 ไม่มีจริง) · **บนหน้าจริง ตั้ง 12 → วัดได้ 13.5 dB = ตกในกรอบของจริง (13.4–15.1) พอดี**

**⛔ ไม่แตะ `dynamics.js` แม้แต่บรรทัดเดียว** · **เก็บทางของ PM ไว้ (`arcMode:'perf'`) ให้วัดเทียบได้ ไม่ได้ทิ้ง**

**ข้อแลก (เขียนบนหน้าเว็บแล้ว): bus = ไหลเฟดเดอร์ → เปลี่ยนแค่ *ความดัง* ส่วนคนเล่นเบาจริงจะเปลี่ยน *เนื้อเสียง* ด้วย**

### 🔴 **ต้องติ๊ก "ฟังทั้งเพลง" ปุ่มนี้ถึงจะมีความหมาย**

**ท่อนที่ตัดมา = 24% แรกของเพลงเท่านั้น** (19.1 วิ จาก 81.5 วิ) · **ไคลแมกซ์อยู่ที่ 58% = ไม่ได้อยู่ในคลิปเลย**

# 🔴 5.4 บั๊ก "โน้ตวินาที 14 ดังผิดปกติ" — **หาเจอแล้ว · เป็นบั๊กจริง · แก้ได้ (ไม่หมด)**

## ต้นเหตุ — **ไฟล์ในไลบรารีดังไม่เท่ากัน แล้วทำนองก้าวข้ามไฟล์พอดีตรงนั้น**

แต่ละไฟล์ครอบ **±1 เสียง** (`60` ครอบ 59–61 · `63` ครอบ 62–64) → **ทำนองเดินจากโน้ต 64 ไป 61 = สลับไฟล์ 63→60 กลางคัน**

**ระดับของไฟล์ที่เพลง #1 ใช้จริง (วัดจาก .ogg ตรง ๆ · ช่วง 0.3–1.3 วิ = พ้นการบวม 200ms แล้ว):**

| ไฟล์ | ระดับ |
|---|---|
| **60** | **−19.0 dB** ← ดังสุด |
| 63 | −21.9 |
| 66 | −24.0 |
| 69 | −34.4 |

→ **ห่างกัน 15.4 dB ในไฟล์ที่เพลงเดียวใช้** (ทั้งไลบรารี `p` = **21.2 dB**)

**ในคลิปจริง:**

| วินาที | โน้ต | ไฟล์ | ดังเกินเส้น |
|---|---|---|---|
| 13.5 | 64 | 63 | +0.1 |
| **14.1** | **61** | **60** | **🔴 +5.5** |
| **15.0** | **59** | **60** | **🔴 +6.9** |

→ **13.5→14.1 กระโดด +5.4 dB มากกว่าที่ arranger สั่ง** · **โน้ตที่ใช้ไฟล์ 60 ทั้ง 8 ตัวโดดขึ้น +3.2 ถึง +6.9 dB สม่ำเสมอ** = ไม่ใช่บังเอิญ

## ⚖️ **ธรรมชาติของเชลโล หรือ ความเพี้ยนตอนอัด?** — ตัวเลขตอบ: **ความเพี้ยน → แก้ได้**

เชลโลจริงความดังต้องไล่ตามระดับเสียง**เรียบ ๆ** · ของจริงที่วัดได้:

| | |
|---|---|
| **สลับทิศขึ้น-ลง** | **10 ครั้ง จาก 16 ช่วง** |
| ก้าวเฉลี่ยระหว่างไฟล์ติดกัน | **5.3 dB** |
| **ก้าวแย่สุด** | **12.6 dB** (ไฟล์ 54→57 ที่ติดกันแท้ ๆ) |

→ **เชลโลจริงไม่กระโดด 12.6 dB ระหว่างโน้ตข้างเคียง** = **เทคที่อัดคนละครั้ง**
→ **หลักฐานหนุน: ไลบรารีมี 4 ชั้น (`p`/`mp`/`mf`/`f`) ไว้แสดงความดังอยู่แล้ว** → ภายในชั้นเดียวกันมันไม่ควรเหวี่ยง 21 dB · **การซิกแซกนี้ไม่ได้อยู่ในดีไซน์ของเขา**
→ `tools/prepare-cello-bakeoff.py` **อบ makeup ตัวเดียวทั้งไลบรารี** → **ความซิกแซกรอดเข้ามาเต็ม ๆ**

## ✅ ตัวแก้ + ผลที่วัดได้

**ปรับความดังรายไฟล์ให้เท่ากัน · normalize ไปที่ค่ากลางของไลบรารีเอง (−23.6 dB)** ไม่ใช่เลขที่ผมตั้ง → **ความดังรวมจึงอยู่ที่เดิม แก้แค่ความซิกแซก**

| | ก่อน | หลัง |
|---|---|---|
| โน้ตไฟล์ 60 (8 ตัว) | +5.5 · +3.2 · +5.1 · +5.0 · **+6.7** · +5.5 · **+6.9** · +4.9 | +0.5 · −1.8 · +0.1 · 0 · **+4.3** · +0.6 · +1.9 · 0 |
| **กระโดด 13.5→14.1 วิ** | **5.3 dB** | **2.5 dB** |

**ทฤษฎีทำนายว่าความดังรวมต้องไม่เปลี่ยน → วัดได้ต่าง 0.8 dB = ตรง** ✅ · แก้ 17 ไฟล์ · ตัดสุด **−10.4 dB** · หนุนสุด **+10.8 dB**

## ⚠️ บอกตรง ๆ — 3 ข้อที่ยังไม่จบ

1. **ไม่หายหมด เหลือ 2.5 dB · ผมยังตอบไม่ได้ว่าที่เหลือมาจากไหน** (สงสัย: `p` บวม 200ms → โน้ตยาวกว่ามีเวลาบวมถึงยอดมากกว่า → โน้ตยาวดังกว่าโดยธรรมชาติ แต่**ยังไม่ได้พิสูจน์ อย่าเพิ่งเชื่อ**)
2. **ดันไฟล์เบาขึ้น +10.8 dB = อาจดันเสียงซ่าขึ้นมาด้วย ผมยังวัดไม่ได้** → **ต้องหู P'Aim**
3. **ตัวเลข noise floor ที่ผมวัดรอบแรก ใช้ไม่ได้ ทิ้งแล้ว** — ผมวัดช่วง 0–50ms คิดว่าเป็นความเงียบ **แต่ `p` บวมช้า ช่วงนั้นคือคันชักเริ่มสีแล้ว** ไม่ใช่ความเงียบ → **ตัวเลข "SNR 3.4 dB" ที่เกือบรายงานไป = ผิด**

## 🪤 กับดักที่เกือบโดน — **เอกสาร smplr บอกผิด**

เอกสารเขียนว่า `volume` = *"0–127 MIDI scale, defaults to 100"* → **ถ้าเชื่อแล้วใส่ `volume: 100` คิดว่าเป็นค่าปกติ = เสียงระเบิด +100 dB**
**วัดจริง:** ไม่ใส่ = −32.2 · `volume:50` = **+17.8** · `volume:100` = **+67.8** → **`volume` คือ dB ตรง ๆ** (บวก N ได้ +N dB เป๊ะทั้ง 2 จุด)
→ **ทดสอบก่อนใช้ทุกครั้ง แม้แต่เอกสารทางการของไลบรารี**
