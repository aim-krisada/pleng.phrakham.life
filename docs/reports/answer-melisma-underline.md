# คำตอบ: เอื้อน "ข้า" ร้องข้าม 3 โน้ต "6 1 6" — พิมพ์ยังไง + เส้นใต้ต่อกันไหม

**ที่มา:** P'Aim ถามจากหนังสือเพลงเล่มพิมพ์ เพลง 141 "สรรเสริญองค์พระผู้เป็นเจ้า" —
พยางค์เดียว "ข้า" ร้องข้าม 3 โน้ต "6 1 6" (โน้ตตัวเลข/jianpu, แต่ละตัวเป็นเขบ็ตหนึ่งชั้น =
มีขีดใต้ 1 เส้น). ในเล่มพิมพ์ ขีดใต้ 3 ตัวลากเป็น **บีมเดียวต่อกัน** (ไม่ใช่ 3 ขีดสั้นแยกกัน).
นี่คือ **เอื้อน** (melisma = 1 พยางค์ข้ามหลายโน้ต).

งานนี้ = วิเคราะห์อ่านโค้ดอย่างเดียว (read-only) · ไม่แก้ src · ไม่ merge · ไม่ deploy.

---

## สรุปสั้น (F60+)

1. **พิมพ์โน้ต:** `6_ 1_ 6_` (ขีดล่าง `_` = เขบ็ต 1 ชั้น) แล้วใส่คำ "ข้า" ที่ช่องพยางค์ของโน้ตตัวแรก
   ตัวเดียว เว้นช่องโน้ตตัวที่ 2–3 ว่าง.
2. **เส้นใต้ต่อกันไหมวันนี้:** **ไม่ต่อ.** ตัวเรนเดอร์วาดขีดใต้แยกเป็นราย "ตัวเลข" (per-digit
   `border-bottom`) โดยตั้งใจ — มีคอมเมนต์ในโค้ดสั่งห้ามต่อเส้นใต้ให้ชัดเจน. เอื้อนถูกวาดเป็น
   **เส้นโค้ง (arc) เหนือกลุ่มโน้ต** แทน ไม่ใช่บีมใต้โน้ต.
3. **ช่องว่าง (gap):** สิ่งที่ P'Aim เห็นในเล่ม (บีมต่อกัน) ระบบยัง **ทำไม่ได้** — เป็นความ
   ตั้งใจของดีไซน์ปัจจุบัน (เอื้อน = arc เหนือ, ไม่ใช่บีมล่าง). ถ้าอยากได้หน้าตาเหมือนเล่ม = ต้อง
   เปิดงานใหม่ (ดู §3).

## 1. หลักฐานจากซอร์สโปรเจกต์

### 1a. การพิมพ์โน้ต + ผูกพยางค์ (โมเดล v2)

- `src/lib/notation.js` — ไวยากรณ์โน้ต: `5_` = เขบ็ต 1 ชั้น (ขีดใต้ 1) · `5__` = เขบ็ต 2 ชั้น ·
  `( )` = slur/เอื้อน รอบกลุ่ม · `~` = ไท · `-` = ลากยาว (บรรทัด 5–11, 45–46).
- โมเดล v2 (`docs/song-model-v2.md`) แยก **ทำนอง (stanza)** กับ **คำ (arrangement.syllables)**
  โดย **1 พยางค์ต่อ "โน้ตที่กินพยางค์" (attack note) 1 ตัว**. โน้ตที่ "ไม่กินพยางค์"
  (held) = `-`, ไท `~`, หรือ **โน้ต pitch เดียวกันใต้ slur**.
- `noteBoxKinds()` (notation.js:143–163) จำแนกแต่ละช่องเป็น `attack` / `held` / `struct`.
  **จุดสำคัญ:** เงื่อนไข held คือ `(note.tieEnd && prevKey === key) || (slur && prevKey === key)`
  — คือ held **ต่อเมื่อ pitch เท่าเดิม** เท่านั้น.

**ผลกับกรณี "6 1 6" (pitch ต่างกัน):**
ต่อให้ครอบด้วย slur `(6_ 1_ 6_)` ทั้ง 3 ตัวก็ยังถูกจำแนกเป็น `attack` (เพราะ pitch ไม่เท่ากัน
6≠1≠6-คนละ octave-context) → `attackSlots = 3` → ระบบ "อยากได้ 3 คำ".
โมเดลปัจจุบัน **จำเอื้อนที่ pitch ต่างกันเป็น held ไม่ได้** — รองรับเฉพาะเอื้อน pitch เดิมซ้ำ
(เช่น `(5_ 5_)`). นี่คือช่องว่างของโมเดล (design doc บรรทัด 28–36 พูดถึง same-pitch เท่านั้น).

**แปลว่าวิธีพิมพ์ให้ได้ 1 พยางค์วันนี้ (workaround):**
พิมพ์ `6_ 1_ 6_` แล้วใส่ "ข้า" เฉพาะช่องแรก เว้น 2 ช่องหลังว่าง. เรนเดอร์ออกมาถูก (คำ "ข้า"
อยู่ใต้โน้ตตัวแรก, อีก 2 ตัวไม่มีคำ) — **แต่** ตัวนับพยางค์จะขึ้นเตือน `1/3 ⚠` (เพราะนับ attack
3 ตัว). คำเตือนนี้ไม่บล็อกอะไร เป็นแค่ธงให้รีวิว เรนเดอร์/พิมพ์ยังออกปกติ.
(จะครอบ slur `(6_ 1_ 6_)` เพิ่มก็ได้ ได้เส้นโค้งเหนือกลุ่มเป็นสัญลักษณ์เอื้อน แต่ ⚠ ก็ยังขึ้นเท่าเดิม.)

### 1b. เส้นใต้ (บีมเขบ็ต) เรนเดอร์ยังไง

- `SongSheet.vue` เรนเดอร์โน้ตผ่านคอมโพเนนต์ `NoteRow` (SongSheet.vue:5, 333).
- `NoteRow.vue` วาดขีดใต้เป็น **`border-bottom` ของ `.num` แต่ละตัว** (NoteRow.vue:227–228):
  ```css
  .num.u1 { border-bottom: 1.5px solid currentColor; }   /* เขบ็ต 1 ชั้น */
  .num.u2 { border-bottom: 4px double currentColor; }    /* เขบ็ต 2 ชั้น */
  ```
- และมีคอมเมนต์ **สั่งห้ามต่อเส้นใต้อย่างชัดเจน** (NoteRow.vue:229–232):
  > "Every eighth/sixteenth note keeps its OWN separate underline so each note reads
  > as its own เขบ็ต — a slur (เอื้อน) is only the arc above and must NOT join the
  > underlines (a long connected underline means something else)."

  แปล: ทุกเขบ็ตมีขีดใต้ **ของตัวเอง แยกกัน** โดยตั้งใจ · เอื้อน = เส้นโค้งเหนือเท่านั้น
  ห้ามเชื่อมขีดใต้ · (มีเหตุผลว่าขีดใต้ยาวต่อกันสื่อความหมายอื่น).
- ไม่มีโค้ดเชื่อมบีมข้ามโน้ตที่ไหนเลย (grep `beam`/`joinUnderline` ทั้ง `src/` — ไม่พบตรรกะเชื่อม;
  ที่ยืดได้มีแต่ **triplet** ที่ยืดขีดใต้ให้เต็มกลุ่ม NoteRow.vue:233).
- เอื้อนถูกวาดเป็น **SVG arc เหนือกลุ่ม slur** แทน (NoteRow.vue:41–53, 133–143 · งาน B076/B062).

**สรุป 1b:** พิมพ์ `6_ 1_ 6_` วันนี้ = ได้ **ขีดใต้ 3 เส้นแยกกัน** ไม่ใช่บีมเดียวต่อกันแบบในเล่ม.

### 1c. ต่อกันไหมวันนี้? — ไม่ (นี่คือช่องว่าง)

**ไม่ต่อ.** เล่มพิมพ์คาดหวังบีมเดียวลากใต้ 3 ตัว (สัญลักษณ์กลุ่มเขบ็ต/เอื้อน). ระบบ pleng
เลือกดีไซน์ตรงข้าม: ขีดใต้แยกราย note + เอื้อนเป็นเส้นโค้งเหนือ. เป็น **ความตั้งใจของดีไซน์
ปัจจุบัน ไม่ใช่บั๊ก** แต่ = หน้าตาไม่ตรงเล่มพิมพ์ที่ P'Aim ถือ.

## 2. คำตอบภาษาพี่เอม (ม.ต้น)

**พิมพ์ยังไง:**
1. ช่องโน้ตพิมพ์ `6_` `1_` `6_` (ขีดล่าง `_` ต่อท้ายเลข = เขบ็ตขีดใต้ 1 เส้น). ได้ 3 ช่องโน้ต.
2. ช่องคำร้อง (พยางค์) ใต้โน้ต: พิมพ์ **"ข้า" ในช่องแรกช่องเดียว** เว้นช่องที่ 2 กับ 3 ว่างไว้.
   → คำ "ข้า" จะไปอยู่ใต้โน้ต 6 ตัวแรก อีกสองตัวไม่มีคำ = ร้องเอื้อนลากเสียง "ข้า" ข้าม 3 โน้ต.
3. ระบบจะขึ้นเตือนเลขนับ `1/3 ⚠` (มันนับว่าโน้ต 3 ตัวน่าจะมี 3 คำ). **ไม่ต้องกังวล**
   เป็นแค่ธงเตือนให้ตรวจ ไม่ได้ห้ามบันทึกและพิมพ์ออกมาก็ถูก.

**หน้าตาที่ได้ (สำคัญ):** วันนี้แอปจะวาด **ขีดใต้แยกกัน 3 เส้น ตัวใครตัวมัน** —
**ไม่ใช่บีมเดียวลากยาวต่อกันเหมือนในเล่มหนังสือ.** ถ้าอยากได้เส้นเดียวต่อกันเป๊ะแบบเล่มพิมพ์
ตอนนี้ยัง **ทำไม่ได้** ต้องให้ทีมเปิดงานทำเพิ่ม.

*(อยากได้เครื่องหมายเอื้อนตอนนี้เลย: ครอบวงเล็บ `(6_ 1_ 6_)` จะได้เส้นโค้งบางๆ โค้งอยู่
**เหนือ** โน้ต 3 ตัว = สื่อว่าเอื้อน แต่ขีดใต้ก็ยังแยกกันอยู่ดี.)*

## 3. ช่องว่างที่พบ (สำหรับ PM พิจารณาเปิดงาน)

มี 2 ช่องว่างจริง ถ้า P'Aim อยากให้ตรงเล่มพิมพ์:

1. **บีมขีดใต้ต่อกัน (render):** ปัจจุบันขีดใต้แยกราย note โดยตั้งใจ (NoteRow.vue:229–232).
   เล่มพิมพ์ใช้บีมเดียวต่อกันใต้กลุ่มเขบ็ต/เอื้อน. ถ้าจะทำ = งาน render lane (คล้าย B062/B076
   ที่ทำ arc) และต้องตัดสินใจ "ต่อเมื่อไหร่" (ต่อทุกกลุ่มเขบ็ต? หรือเฉพาะในวงเอื้อน?) — ชนกับ
   ดีไซน์เดิมที่จงใจแยก ต้องให้ P'Aim เคาะ convention ก่อน.

2. **โมเดลเอื้อน pitch ต่างกัน (data):** `noteBoxKinds` มาร์ก held เฉพาะ **pitch เดิมซ้ำ**
   ใต้ slur เท่านั้น (notation.js:158). เอื้อนข้าม pitch ต่าง (6 1 6) จึงมาร์กเป็น held ไม่ได้ →
   นับ `attackSlots` เป็น 3 → เตือน `⚠` ทุกครั้ง. ถ้าอยากให้เว้นคำได้สะอาด (ไม่ติดธง) ต้องขยาย
   กฎ held ให้ครอบ "โน้ตในวง slur ที่ไม่ใช่ตัวแรก = held ไม่ว่า pitch ใด" (แก้จุดเดียวใน
   notation.js) — แต่กระทบตัวนับพยางค์ทั้งระบบ ต้องให้ SA ออกแบบ + tester gate.

**หมายเหตุ:** ทั้งสองข้อ **ยังไม่ deploy ไม่กระทบ public** · เป็นข้อเสนอ ไม่ใช่บั๊กด่วน ·
P'Aim workaround พิมพ์ได้เลยตามข้อ 2 (เนื้อร้องถูก, แค่หน้าตาเส้นใต้ไม่ตรงเล่ม + มีธง ⚠).

## 4. มาตรฐานโน้ต (jianpu + สากล) ว่าไง — refinement สำคัญ

**แหล่งในโปรเจกต์:** `docs/reports/jianpu-ly-study.md` ยืนยัน LilyPond/jianpu-ly
**"วางคานใต้ตัวเลข (jianpu วางคานใต้โน้ต)"** = มาตรฐานลากคานต่อกันใต้เลข.

มาตรฐานโน้ตตัวเลข (และโน้ตสากล) แยก **2 เรื่องนี้ออกจากกันชัดเจน:**

1. **ขีดใต้ต่อกัน = คาน (beam) = เรื่องจังหวะล้วน.** ขีดใต้เลข = ตัวบอกค่าโน้ต (1 ขีด=เขบ็ต,
   2 ขีด=เขบ็ตสองชั้น) — 減時線. เมื่อเขบ็ตหลายตัวติดกัน มาตรฐาน **ลากขีดใต้ต่อเป็นเส้นเดียว**
   ตลอดกลุ่ม = คานเดียวกับการ beam ตัวเขบ็ตในโน้ตสากล. บอก **จังหวะ** เท่านั้น **ไม่เกี่ยวคำร้อง**.
   → หนังสือที่ลาก `6–1–6` ต่อกัน = **การ beam เขบ็ต 3 ตัวตามปกติมาตรฐาน** ไม่ใช่สัญลักษณ์เอื้อน.

2. **เอื้อน (1 พยางค์หลายโน้ต) = เส้นโค้ง slur เหนือโน้ต** (jianpu 圆滑線) + วางคำใต้ **โน้ตตัวแรก
   ตัวเดียว**. โน้ตสากลก็ทำเหมือนกันเป๊ะ (slur arc + คำใต้ตัวแรก). **เส้นโค้งเหนือนี่ต่างหาก
   คือตัวมาร์กเอื้อนตามมาตรฐาน — ไม่ใช่คานใต้.**

**เทียบ pleng กับมาตรฐาน:**

| องค์ประกอบ | มาตรฐาน | pleng | ผล |
|---|---|---|---|
| มาร์กเอื้อน | เส้นโค้งเหนือ + คำใต้ตัวแรก | วาด arc เหนือ (slur `( )`) + คำใต้ตัวแรก | ✅ **ตรงมาตรฐาน** |
| คาน (เขบ็ตติดกัน) | ขีดใต้ **ต่อกัน** เป็นคานเดียว | ขีดใต้ **แยกราย note** | ❌ **ผิดมาตรฐาน** |

**Refinement ต่อ §1c/§3:** ที่จริง **การมาร์กเอื้อนของ pleng ตรงมาตรฐานอยู่แล้ว** (arc เหนือ = เอื้อน
จริง). จุดเดียวที่ pleng ต่างจากมาตรฐาน = **คาน** — เล่มลากต่อเพราะ **นั่นคือ beaming มาตรฐาน**
ไม่ใช่ "หน้าตาแบบเล่ม" ที่เป็นรสนิยม. → gap ข้อ 1 (§3) จึงเป็น **"ทำให้ตรงมาตรฐาน jianpu"**
ไม่ใช่แค่ "เลียนแบบเล่ม".

**⚠️ ข้อสังเกตโค้ด:** คอมเมนต์ NoteRow.vue:229–232 อ้างว่าขีดใต้ต่อกัน "means something else" —
**ไม่ตรงมาตรฐาน**: ใน jianpu มาตรฐาน ขีดใต้ต่อกัน = "เขบ็ตที่ beam รวมกัน" เฉยๆ. การตั้งใจแยกขีดใต้
จึงตั้งอยู่บนความเข้าใจ convention ที่คลาดเคลื่อน → PM ควรชั่งใหม่ตอนพิจารณา gap ข้อ 1.
