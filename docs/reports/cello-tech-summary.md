# สรุปเทคนิค — เชลโล spike (Karoryfer CC0 + เปียโนร่างทอง)

เอกสารนี้สรุป **ทุกเทคนิค** ที่ใช้ทำเสียงเชลโลคลอทำนองในหน้าฟัง `docs/spikes/cello-listen.html` ของ
pleng.phrakham.life — สำหรับให้ผู้เชี่ยวชาญ (G) ทบทวนและเสนอแนวทางอื่น

**เป้าหมาย (P'Aim):** "รวมวง เปียโนร่างทอง + เชลโลที่ลื่นหู ไม่แสบแก้วหู เพราะระดับหนึ่ง พอแล้ว · ไม่มีทาง
เหมือนคนเล่นจริง 100% แต่ได้ 80% จาก 20% effort ก็ดีพอ" · **ยังเป็น spike** (ยังไม่เข้าแอปจริง)

**หลักการเหล็ก (เหมือน golden piano):** ทุกเทคนิคต้องเป็น **สมการ/กฎอัตโนมัติที่ใช้ได้ทั้งคลัง (124+ เพลง)**
ห้ามจูนรายเพลง · deterministic (MP3 == live · สุ่มผ่าน seeded RNG เท่านั้น) · เล่นโน้ตตรงตามแผ่น (honest-to-sheet)

---

## 0. สถาปัตยกรรมโดยรวม
- **ใช้เครื่องยนต์เดียวกับเปียโนร่างทอง:** `arrange()` (pure function · voicing→pattern→dynamics→REFEREE)
  สร้าง `PerfEvent[]` (role/pitch/beat/gain/timing) · เชลโล = **เอา voice "melody" ไปเล่นด้วย sampler เชลโลแทน**
  ส่วนเปียโนเล่น role ที่เหลือ (คลอ) · ทั้งคู่เข้า reverb bus เดียวกัน (ห้องเดียว)
- **ความดัง/จังหวะของเชลโลมาจาก `arrange()` โดยตรง** (gain → velocity) ไม่ได้สร้างระบบdynamicsใหม่
- เชลโลคุมด้วยพารามิเตอร์ของ `renderClip()` (spike · แยกจากโค้ด deploy)

## 1. ตัวอย่างเสียง (sample layer)
- **Karoryfer x bigcat cello · CC0** · close-miked · อัดแบบ**ไม่มี vibrato**
- ไลบรารีอัดจริง **17 ระดับเสียงเท่านั้น** (ห่างกันทีละ minor third · MIDI 36–84) × 4 ชั้นความแรง
  `p`/`mp`/`mf`/`f` × 2 คันชัก (down `_d` / up `_g`)
- **เราใช้:** ตัวโน้ต (body) = ชั้น **`p`** (คันชักเบา = เนื้อเสียงทึบสุด/แสบน้อยสุด · พิสูจน์แล้วว่าเป็น
  เนื้อเสียงคนละแบบ ไม่ใช่ `mf` ที่หรี่ลง) · หัวโน้ต (head) = **`mp` staccato**
- **โหลดแยกเป็น instrument ต่อชั้น** (velRange เต็ม) — smplr gotcha: ถ้ายัดหลายชั้นเป็น velRange groups
  ความดังจะรีเซ็ตที่รอยต่อ

## 2. เทคนิคเสียง (ทุกข้อ = กฎอัตโนมัติต่อโน้ต · ไม่เจาะจงเพลง)

### 2.1 Marcato — หัวโน้ตสั้น + ตัวลาก (แบ่งตาม *เวลา*)
- หัว = `mp` staccato สั้น (`ampeg_hold` 200ms) **ความแรง 5%** ลงตรงบีต · ตัว = `p` ลากยาว
- หัวคมทำหน้าที่ "บอกจังหวะ" → หูยึดหัวเป็นบีต → ตัว `p` ที่บวมช้าไม่รู้สึกช้า
- **ไม่ใช่ crossfade 2 ชั้นของโน้ตเดียว** (อันนั้น = "เชลโล 2 ตัว" ที่ทำ spike ก่อนพัง) — นี่คือแบ่งตามเวลา
  ตามที่คนอัดทำเองใน `vc_arco_marcato_map.sfz`
- ค่าที่ P'Aim เคาะ (default ถาวร): หัว `mp` · แรง 5% · ตัว `p`

### 2.2 Negative delay (เลื่อนเวลาตัวโน้ต 10ms)
- คันชักบวมช้า (p วัดได้ ~200ms) → ยิงตรงบีตจะได้ยิน "สาย" หลังเปียโน (เปียโนถึงครึ่งเสียงใน 0ms)
- ยิงตัวโน้ตก่อนบีตตามค่า attack ที่วัดได้ → หูได้ยินโน้ตตรงบีต · P'Aim เคาะ 10ms (คู่กับหัวคมแล้วไม่ต้องเลื่อนมาก)

### 2.3 Per-file level normalize (แก้ "ซิกแซกความดังของไลบรารี")
- **ปัญหา:** 17 ไฟล์อัดคนละเทค → ความดังเหวี่ยง (ในชั้น `p` เหวี่ยงถึง ~21 dB · ไฟล์ข้างเคียงต่าง 12.6 dB)
  = เสียง "กระโดด" ระหว่างโน้ต (P'Aim ได้ยิน "วินาที 14 ดังผิดปกติ")
- **แก้:** normalize แต่ละไฟล์ไปที่ **ค่ากลางของไลบรารีเอง (−23.6 dB)** → ความดังรวมไม่เปลี่ยน แก้แค่ซิกแซก
- กฎกลาง · วัดจากไลบรารี ไม่ใช่เจาะจงเพลง

### 2.4 Vibrato (LFO ทำเองใน Web Audio · ใช้ค่าของคนอัด)
- คนอัดใส่ vibrato ไว้ใน sfz แต่ปิดไว้ + คอมเมนต์เหตุผลทุกบรรทัด → เรารับ**ค่า**มา: 4 Hz พื้น ·
  หน่วงก่อนสั่น 177ms · ค่อยไล่ลึก 177ms · ความลึกสูงสุด 22 cents (เพดานที่เขาบอกว่า "เกินนี้ฟังสังเคราะห์")
- **กฎอัตโนมัติ: สั่นเฉพาะโน้ตยาว** — โน้ตสั้นกว่า 354ms (หน่วง+ไล่) สั่นไม่ทันโดยธรรมชาติ → ไม่สั่น ·
  ไล่ถึงเต็มที่ 708ms · วัดจริงข้ามเพลง: #1 50% · #4 80% · #9 100% ของโน้ตสั่น (ต่อเพลงอัตโนมัติ ไม่จูน)
- **key ที่ *ความยาวโน้ต* ไม่ใช่ tempo** · deterministic (per-note phase = seeded RNG)
- ยังไม่เปิด: ความไม่สม่ำเสมอ (lfo2) · EQ ขยับตอนสั่น (มีปุ่มให้ลอง)

### 2.5 ⭐ Shift-based treble taming (หัวใจของ "ความสม่ำเสมอ" · ใหม่ 18 ก.ค.)
- **ปัญหาราก:** ไลบรารีมีแค่ 17 ระดับ → โน้ตระหว่างนั้นถูก **pitch-shift** จากไฟล์ใกล้สุด → formant ขยับ:
  - ดึง**ขึ้น** (เล่นสูงกว่าไฟล์) = สว่าง/บาง = **"แหบ"** (วัด: +2.9 dB เหนือ 1.5kHz เทียบโน้ตตรงไฟล์)
  - ตรงไฟล์พอดี = เต็ม/อุ่น = **"ทุ้ม"** (โน้ตอ้างอิงที่อยากให้ทุกตัวเป็น)
  - ดึงลง = กลางๆ (+1.5 dB)
  - **P'Aim ได้ยินสลับ "แหบ↔ทุ้ม" เป็นตัวๆ · หูตรง 4/4 จุดกับทิศการดึง**
- **แก้:** high-shelf @2.2kHz cut **ถ่วงน้ำหนักตามทิศการดึง** ต่อโน้ต — ดึงขึ้น = เต็ม · ดึงลง = 0.6 · ตรงไฟล์ = 0
  → กด "โน้ตแหบ" ลงมาเท่า "โน้ตทุ้ม" (วัด: spread 2.9 → ~1.4 dB) · ปุ่ม "ความสม่ำเสมอ" คุมความแรง
- **key ที่ *ระยะ+ทิศการดึงเสียง* → ใช้ได้ทุกโน้ตทุกเพลง** (คำนวณจาก MIDI โน้ต vs 17 ไฟล์)
- automate ผ่าน `BiquadFilter.gain.setValueAtTime` ต่อโน้ต (ทำนอง mono · step ที่ attack = ไม่ได้ยินรอยต่อ)

### 2.6 Long-note tail darkening (แก้ "หางโน้ตยาวสว่างขึ้น" · ใหม่ 18 ก.ค.)
- **ปัญหา:** คันชักเบา `p` ลากค้างนานๆ **หางโน้ตค่อยๆ สว่างขึ้นเอง** (โน้ต 2 วิ ไต่ ~4 dB · เนื้อคันชักสะสม)
  = "แหบสั้นๆ" ปลายโน้ตยาว (P'Aim ได้ยินราววินาที 7.8 ของโน้ตที่ลากตั้งแต่ 6.8)
- **แก้:** โน้ต**ยาว >1 วิ + ถูกดึงเสียง** → ramp cut ไปที่ **1.5× ของปุ่ม** ที่หางโน้ต (linearRamp) · โน้ตตรงไฟล์
  (ทุ้ม) ไม่แตะ → วัด: วินาทีที่สว่าง −4.1 → −5.5 (เท่าโน้ตทุ้ม −5.4)
- **key ที่ *ความยาว+การดึงเสียง* → กฎกลาง** · ⚠️ ค่า "1.5×" = empirical (เพราะ dB ของ shelf ไม่แปลงตรงกับ
  แบนด์ >1.5kHz) — **จุดที่ยัง "hacky" สุด ควรถาม G ว่ามีวิธีสะอาดกว่าไหม**

### 2.7 Arc (เส้นดัง-ค่อยทั้งเพลง · optional)
- overlay บน gain ของ `arrange()` (หรือ ride ทั้ง mix) · รูปทรงไคลแมกซ์ ~58% ของเพลง
- ⚠️ ดันดังขึ้น = สว่างขึ้น = แสบกลับมา (P'Aim สังเกต) → ใช้น้อยๆ · default = ปิด

### 2.8 อื่นๆ
- **Balance:** เชลโลตั้งระดับเท่า "ทำนองของเปียโน" ที่วัดได้ (calibrate ต่อท่อน ไม่ใช่ค่าเฉลี่ยไลบรารี)
- **Reverb:** bus เดียวกับเปียโน (ห้องเดียว)
- **พักถาวร:** คันชักคู่ round-robin (`_d`/`_g` t50 ต่าง 200ms → กระตุกเป็นคาบ · แก้ไม่ได้เชิงโครงสร้าง)

## 3. ข้อจำกัด (เพดานที่ต้องบอก G)
1. **17 ระดับเสียง = ต้นเหตุหลัก** — pitch-shift ขยับ formant · เราแค่ "กลบ" ด้วย EQ ตามทิศการดึง
   ไม่ได้แก้ formant จริง · **ถ้าได้ตัวอย่างเสียงที่อัดครบทุกโน้ต (chromatic) ปัญหานี้หายเกือบหมด**
2. **close-miked** = ได้ยินคันชักครูดจ่อหู · ไม่มีระยะห่าง/ห้อง (แผ่นจริงไมค์ห่าง 2-3 เมตร)
3. **Web Audio ทำ formant-preserving pitch-shift ตรงๆ ไม่ได้** (ต้อง PSOLA/phase-vocoder)
4. **Claude/SA ฟัง mix ไม่ออกว่า "เพราะ"** — วัดได้แค่ตัวเลข (peak/centroid/RMS/spread) · **หู P'Aim ตัดสิน
   "แรงแค่ไหนพอดี" ทุกครั้ง** → ทุกปุ่มความแรงต้องให้ P'Aim หมุนหาเอง ไม่ใช่ Claude กำหนด

## 4. คำถาม/ไอเดียที่อยากให้ G ช่วยคิด
- **Formant-preserving pitch shift** ใน Web Audio (PSOLA / phase vocoder / world vocoder) — คุ้ม effort ไหม
  เทียบกับหา sample ใหม่?
- มี **cello sample ฟรี (CC0/PD) ที่อัด chromatic ครบ + หลาย dynamic** ที่คุณภาพดีไหม?
- **Convolution reverb / distance model** ลดความ close-mic harsh — impulse response แบบไหนเหมาะ?
- **Spectral smoothing ข้ามโน้ต** (ให้ timbre ต่อเนื่อง) แบบที่ไม่ใช่แค่ EQ shelf — มีวิธี principled กว่า
  "1.5× tail ramp" ของเราไหม?
- หลักการรวม: เราไล่ตาม "ทำให้ทุกโน้ตเนื้อเสียงเท่ากัน" ถูกทางไหม หรือควรยอมรับความต่างแล้วไปโฟกัสอย่างอื่น?
