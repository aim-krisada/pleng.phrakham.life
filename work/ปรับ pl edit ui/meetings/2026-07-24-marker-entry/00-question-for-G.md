ผมเป็น SA ของแอปโน้ตเพลงโบสถ์ (jianpu) · กำลังออกแบบ **การป้อนสัญลักษณ์วนร้อง/นำทาง** (Segno/Coda/D.C./D.S./Fine
+ กระโดดกลางห้อง) เข้าตัวแก้ inline · ผู้ใช้ = อาสาสมัครโบสถ์ ไม่ใช่นักดนตรีอาชีพ (พี่เปา คีย์เพลงวันละหลายเพลง).
resolver + canonical data shape เสร็จแล้ว · รอบนี้เจาะ **UX การป้อน**. ผมมีจุดยืนทั้งชุด อยากให้ค้านตรงที่ค้านได้จริง.

**Q1 — preset ภาษาคน + dropzone vs ประกอบเอง.** ผมเลือกให้ผู้ใช้กด preset "D.S. al Coda" แล้วระบบ "งอก"
placeholder 3 จุด (Segno/To-Coda/Coda) ให้ลากไปวาง + ผูก id อัตโนมัติ (กัน broken routing) แทนให้ประกอบเอง 4 ชิ้น
แบบ MuseScore. สำหรับมือใหม่ นี่คือแนวที่ดีที่สุดไหม? มี pitfall อะไร (เช่น ผู้ใช้งงว่า placeholder คืออะไร / วางผิดจุด)?
มี precedent ที่ทำ dropzone/auto-link ดี (iReal Pro, Dorico) ที่ผมควรดู? ขอชื่อ/URL.

**Q2 — วาง marker กลางห้อง (mid-bar) ให้ไม่งง.** ระบบผมให้เลื่อน caret ไประหว่างโน้ต 2 ตัวกลางห้อง แล้ววาง marker
(glyph โผล่กลางห้องตรงนั้น). สำหรับคนไม่ใช่มือโปร การ "แตะช่องว่างระหว่างโน้ต" เพื่อวางจุดกลางห้อง — ชัดพอไหม หรือควรมี
affordance อื่น (เช่น แตะโน้ต แล้วเลือก "วางก่อน/หลังโน้ตนี้")? MuseScore/Dorico ทำ mid-measure marker ยังไง (เลือกโน้ต
แล้วใส่ vs คลิกตำแหน่ง)? ขอ URL.

**Q3 — เห็นการไหล: breadcrumb "ลำดับเล่นจริง" vs เส้นโยง.** ผมเลือกแถบ linear `Intro ➔ ข้อ1 ➔ รับ ➔ ข้อ1(D.S.)
➔ Coda` (อัปเดต real-time) แทนเส้นโยงข้ามหน้า (รกบนจอเล็ก). ถูกทางไหมสำหรับจอมือถือ? มีงานวิจัย/ตัวอย่างที่ยืนยันว่า
flattened linear อ่านง่ายกว่า spatial connector บนจอเล็ก? ขอแหล่ง.

**Q4 — ลบเป็นชุด (delete cascade).** ลบคำสั่ง "D.S. al Coda" ที่มี placeholder Segno/Coda ผูกอยู่ — ควรถามลบทั้งชุด
หรือปล่อย marker ค้าง (แล้วเตือน orphan)? มาตรฐาน editor (MuseScore/Sibelius) จัดการลบ jump ที่มี marker คู่ยังไง?

**Q5 — จุดตายที่ผมมองไม่เห็น** โดยเฉพาะตอน **ใช้ทั้งวัน** (พี่เปาคีย์หลายเพลง/วัน) — flow การป้อน jump ทั้งหมด
(เรียกเมนู → preset → วาง → เห็นผล → แก้/ลบ) มีจุดไหนที่จะช้า/พลาด/งง ที่ผมควรกันไว้ก่อน?
